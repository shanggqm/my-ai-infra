---
description: "依据仓库事实生成或精简优化根目录 AGENTS.md"
---

为当前仓库创建或精简更新根目录 `AGENTS.md`。它保存每次任务开始时都值得加载的最小仓库上下文，帮助快速定位工作、遵守约束和选择验证入口。直接完成，只处理这份文件。

## 1. 确认范围并查证事实

先检查 Git 根目录、工作区修改、已有 `AGENTS.md` 的内容与文件类型，阅读 `README.md` 和已有贡献规范。当前仓库是子模块时，以子模块为范围。根文件为软链接时，确认真实正文位置及是否与 `CLAUDE.md` 共享；断链、循环链接或仓库外目标须暂停写入并说明。

从入口了解项目用途、技术栈、关键目录和工作流程，再沿准备收录的事实查证，按需阅读清单、锁文件、脚本、CI 配置、局部规则、契约和代表性代码或测试。无需遍历全部模块、需求目录或历史材料。

- 命令：核对实际定义、执行目录、前置条件与副作用；不根据技术栈猜测。
- 路径：确认唯一可编辑源、生成物、仓库边界及准备引用的文档确实存在。
- 约束：区分明确规范与当前实现；代码和规范冲突时记录差异，不用实现自动覆盖规范，不把局部约定扩大到全仓。

不扫描依赖和构建产物，不读取真实凭据，不为调研执行安装、部署或数据迁移。

## 2. 筛选内容与引用

逐条判断候选内容：它影响哪些任务？遗漏后会造成什么具体错误或重复探索？同样的信息是否已有表达？只保留有来源且有实际增量价值的内容。

| 去向 | 收录条件 |
|---|---|
| 根文件直接写 | 跨任务适用、相对稳定，影响工作定位、源码边界、全仓约束或验证选择 |
| 保留按需入口 | 服务一类反复出现的任务，入口稳定，且目录职责和已有条目不足以指导查阅 |
| 留在局部上下文 | 仅涉及某个需求、模块实现、阶段进度或历史记录 |

引用必须能写成“做什么时，读取什么”。同一主题优先保留一个权威入口；已在目录职责、命令或规则中表达的信息不再重复列入参考。按需入口不意味着每次任务都要读取全文。

不枚举具体需求的 PRD、技术方案、评审、测试报告，不维护按编号、版本或日期持续增长的链接清单。需求材料通常只需一条目录职责说明，例如 `mai-specs/：按需求组织的规格、方案与验收记录`；只有定位规则不直观时才补充必要入口。示例路径须按当前仓库事实替换，不存在就省略。

某份任务文档若承载唯一有效的全仓约束，提炼该约束并保留必要出处；不顺带收录整个需求的材料。文档的重要性、篇幅或最近被阅读过，都不能单独成为收录理由。

更新已有文件时：

- 保留明确且仍有效的约束、授权边界、操作顺序和验收标准，合并重复表达。
- 有新依据时修正过时事实；删除产品宣传、通用常识、任务进度、重复引用和已确认失效的说明。
- 移除局部细节前，确认它仍可在原有局部文档中找到；仅存在于根文件的明确要求，保留必要表述及适用范围。
- 无法确认是否失效的明确要求先保留；缺少依据的普通信息省略。只有冲突会改变业务承诺、扩大权限或降低验收标准时，才集中询问必要问题，其余部分继续完成。

## 3. 编写最小可用正文

以 `# AGENTS.md` 和一句用途说明开头。按实际内容组织以下部分，允许合并或省略，不凑章节、表格和条数：

- **项目概况**：简述用途、主要技术栈与影响开发的架构事实。
- **关键目录与真源**：用短列表或带职责注释的目录树说明工作入口、唯一源和生成物；不展开需求编号或完整文件树。
- **工作与验证入口**：列出常用命令及不同变更必须执行的检查，交代目录和必要前置条件；相同命令只定义一次，不复制完整 scripts。
- **全仓约束**：保留项目特有的边界、禁止事项、必要顺序和同步要求；局部要求明确作用域。

确有必要时补充“按需查阅”，只放前文没有覆盖的条件入口。已有维护规则并入对应条目，不另设重复清单。

正文主要使用中文；已有明确语言要求时沿用。命令和标识符保持原文，链接使用普通 Markdown。所有内容须有实际依据，不照搬示例、不留占位符、不加入通用编程提醒或本次调研过程，不凭空增加审批和检查要求。

优先压缩重复介绍、局部细节和可直接发现的信息，保持必要约束的完整含义。新增或归档需求通常不应导致根文件增长。

## 4. 写入、复核与交付

写入前重新读取目标，保留并合并已有未提交及并发修改，保留受管区块；无法安全合并时暂停冲突部分。根文件指向仓库内正文时编辑真实正文，保留软链接及共享关系，不顺带修改其他规则文件。

写入后阅读完整文件并核对差异：

- 命令、路径和约束有来源，适用范围准确；已有明确要求未被误删或削弱。
- 同一事实只表达一次，没有需求材料清单、重复入口、空章节和任务记录。
- 增加一批普通需求文档后，本文件仍可保持不变。
- 仅需专题任务查阅的资料有明确触发条件，未被写成全任务必读。
- 原有未提交内容、受管区块、软链接和共享正文关系得到保留。

按仓库要求运行适用于文档修改的检查；只静态核对过的命令不得报告为运行通过。已有文件准确精简时允许无变更。

交付文件路径、主要增删及原因、实际检查结果和未解决冲突。若联动影响共享正文的 `CLAUDE.md`，说明这一点。
