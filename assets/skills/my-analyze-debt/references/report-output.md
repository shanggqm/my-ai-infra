# 报告输出约定

在选择模板和写入报告时读取。本约定自包含，不要求安装其他 Skill 或创建规格工作区。

## 模板与已有报告

新报告依次采用：本次明确指定的模板 → 项目 `mai-specs/_templates/DEBT_ANALYSIS.tmpl.md` → [Skill 内置模板](../assets/templates/DEBT_ANALYSIS.tmpl.md)。项目覆盖不存在时正常回退；明确模板或已经存在的覆盖不可读、损坏时报告具体问题，不静默跳过。实际使用来源写入报告。

明确复查已有报告时按原结构增量维护，保留同根因 ID、人工批注与决定来源。重新确认位置、约束和证据是否仍适用；旧测试通过不能证明当前已解决。新增发现使用该报告内未占用的 ID，不建立隐含的全仓台账。

## 路径选择

1. 用户明确指定的报告路径优先，仍须符合下述写入边界。
2. 明确关联既有 Feature 时，读取该项目 `mai-specs/FEATURE_LAYOUT.json` 的 `artifacts` 数组，定位 `id: "code-review"` 条目的 `path`；将 `DEBT_ANALYSIS.md` 放在该产物的同目录。路径相对 Feature 根目录。契约缺失时使用 `<Feature>/review/DEBT_ANALYSIS.md`。
3. 独立分析默认写入 `<项目>/docs/technical-debt/YYYY-MM-DD-<scope>.md`。`scope` 取可读模块名，全仓用 `repository`；仅使用字母、数字、汉字、连字符或下划线，不含路径分隔符或 `..`。日期使用分析时的实际日期。

关联 Feature 的契约已存在但损坏、映射缺失/重复或路径非法时报告问题，不静默改用默认路径。不新增 layout artifact；不得占用任何已登记阶段产物，即使 `code-review` 本身恰好命名为 `DEBT_ANALYSIS.md`。遇到命名冲突用同目录未占用的 `DEBT_ANALYSIS-02.md` 等名字，并说明实际路径；契约错误须先解决或取得明确替代路径。

## 写入边界

- 写前核对项目真实根、目标及父目录类型和链接关系。仅按需建目录；不沿未知目录软链接写入，不修改外部链接目标。显式外部路径也须在当前授权范围内，不能从分析请求推定外部写权限。
- 宿主因权限拒绝写入后，在对话中交付并注明未落盘；不换工具、改命令或关闭沙箱重试被拒动作。
- 同日同范围重名时，只有明确复查该报告才更新；新分析使用 `-02`、`-03` 等未占用后缀。指定路径已有无关文件、目录占位或不明链接时保留现场，改用合法替代路径并告知，或报告具体阻塞。
- 更新前重读目标确认内容未被他人更改；保留未参与本次分析的内容与人工决定，不能用模板覆盖整份既有报告。
- 无确认债务时可省去空表，用短结论说明已检查范围与剩余未知。只有候选时清楚标注待核验，不算作已确认数量。

## 最小信息

每份报告保留范围、排除项、基线及相关工作区指纹、有效依据、实际模板、已执行与未执行验证。每项确认发现可从定位证据追溯到持续成本和行动理由；没有历史时写归因未知，推断成本写成立条件。

有明确治理项时保留 A 全局最优与 B MVP 的比较、推荐依据和下一步选择题；自定义模板或旧报告缺这些位置时增量补充。无治理项或证据不足时改为保持现状／补证选择。用户未答复标待选择，已有选择保留来源、范围及执行授权，不由推荐或默认选项代填。

延期、接受、关闭分别保留决定或验证来源。复查触发应具体，如规则调整、下次修改或任务完成；“后续关注”不能替代退出条件。报告只提出规则与测试回流位置，写回在后续已授权任务中完成。
