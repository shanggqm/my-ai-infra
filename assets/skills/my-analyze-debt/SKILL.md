# 分析技术债

以持续成本机制判断债务：说明下一次什么变化，会让谁额外理解、修改、验证或协调。结论要有可定位的证据、成立条件和反例检查；风格、文件大小、相似度和 AI 生成身份仅可作为调查线索。

本阶段交付债务分析、解决方案与下一步选择。偿债、创建 Feature、修改团队规则或个人记忆属于后续工作；用户选择方案后，按已有授权交回编排者继续。

## 输入与范围

- 从请求定位项目和模块、目录或业务链路；可选目标、基线、既有报告与输出路径。没有 Feature、PR、历史记录也可以开始。
- 默认检查请求范围的当前快照及必要上下游。歧义影响范围或核心判断时澄清，其他可独立取证部分继续；扩大为全仓分析须有依据及授权。
- 已有规则、债务报告和团队决策作为输入，先核实有效性。缺资料记录未知，不自行补造业务政策、Owner、修改趋势或团队认知。

## 分析流程

### 1. 固定事实与预期

- 记录真实项目根、HEAD 与相关 staged / unstaged / untracked 内容和指纹；无 Git 时记录文件清单、内容摘要及时间。只收集与范围有关的信息，报告不复制敏感值。
- 读取有效 AGENTS / 局部规则、README、契约、实际调用方、实现和测试，梳理职责、状态、核心规则维护源及验证入口。规则与实现冲突分列，不用现状自动替代预期。
- 优先追踪业务核心、频繁修改、多人依赖的交汇点；频率和协作依赖须有来源，缺失时按已知业务影响选重点并注明限制。

### 2. 沿路径形成候选

- 按需阅读[债务分类参考](references/debt-taxonomy.md)，从调用链、数据流、消费者和失败路径取证。类别用于找线索，未发现项不凑数量。
- 对每个候选建立“事实 → 机制 → 具体后续变化 → 额外成本”的因果链，关联真实文件、符号、行号及版本；事实、条件性推断和待核验分别表达。
- 有可靠比较基线才区分新增、放大和历史；否则写“当前快照，归因未知”。单次缺陷可单列，说明持续成本机制后才同时归为债务。
- 认知与责任断层须有团队确认、决策记录或实际交接证据；没有负责人文件、陌生代码和作者数量不足以确认。

### 3. 查反例与验证

- 核对领域差异、统一生成源、有效例外及现有防护。对外观相似的实现先确认是否表达同一规则；对临时分支先查当前消费者和退出条件。
- 默认静态核验。执行现有测试前核查副作用和授权，只在安全环境运行，记录实际命令、版本、退出码与观察；缺条件时给补验方法，不为取证修改受审代码、安装依赖、执行迁移或访问生产。
- 同一根因合并多处证据，多类别标签不重复计算收益。证据不足的候选单列，已经失效或被反证的判断不保留为确认发现。

### 4. 排序、比较方案与拆分任务

- 先单列紧急正确性、安全或数据风险及处置建议；债务排序不能延后其处理，也不扩大执行授权。
- 根据业务影响、修改频率、共同依赖、持续成本及治理代价和回归风险解释排序，不用固定总分或分类顺序代替判断。未知项保留，允许建议观察、触发再评估或保持现状。
- 对拟治理的重点债务，至少比较两套可执行方案：A「全局最优」追求当前目标与约束下的长期整体收益，说明最优依据与假设；B「MVP」以最小改动和影响面取得有效改善，优先易于实施。两者都须满足正确性、安全和现行契约，不为区分方案扩大重构。
- 按[报告模板](assets/templates/DEBT_ANALYSIS.tmpl.md)比较方案的动作、影响、代价、收益、剩余债务与验证，说明 B 演进到 A 的触发条件并给出推荐理由。相关根因可合并设计，避免每个发现复制两份长方案。
- 按方案关联少量有限任务，明确范围与非目标、保留行为、动作、依赖、验证、退出和回滚条件；共用任务只写一处。代码减少或文件重排不能单独证明成本改善。
- 建议与决定分开。接受或延期须有真实决定来源和复查条件；Owner 未知写待确认，当前证据不足时不宣称已解决。

## 输出与下一步选择

- 输出报告时按[报告输出约定](references/report-output.md)选择模板，写入前核对安全路径；内置[报告模板](assets/templates/DEBT_ANALYSIS.tmpl.md)可裁剪，保留范围、基线、证据、成本、判断和验证缺口。
- 复查保留发现 ID 与人工批注，重验旧结论；新变更影响旧证据时标待复查。报告更新不自动修改其他产物。
- 请求范围的重点路径已覆盖且未知项明确，或必要证据受阻时交付。无确认债务或缺少决定性证据时，说明覆盖与补证步骤，不凑治理方案。
- 返回报告、推荐理由与验证缺口后，提出具体选择题：A 全局最优、B MVP、C 暂缓／先补证，并说明各自下一步。有交互选项工具则使用，否则在对话列出选项；等待用户选择，不把推荐当决定。已有明确选择时直接记录并交接，不重复询问。
- 记录用户选择及范围；选择方案本身不补足实施授权。后续治理按已有授权推进，有当前验证后再回流到有效约束、契约与回归用例。

维护此 Skill 时用[行为评测](evals/cases.md)核对判断质量与边界；资源装配通过不能代替实际行为证据。
