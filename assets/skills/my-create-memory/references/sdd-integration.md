# SDD 个人记忆接入与委派

## 开始时按需读取

my-create-memory 已安装且 runtime 可用时，使用它的 scripts/my-ai-infra.mjs 执行 `memory recall --project <项目绝对路径> --scene <当前阶段>`；自定义个人库始终携带同一 --home。阶段映射：my-create-feature → feature、my-create-prd → prd、my-create-design → design、my-review-design → design-review、my-create-test-plan → test-plan、my-implement-code → implement、my-review-code → code-review。

将返回的 context 用作个人偏好，按条目边界使用；当前指示、团队硬约束和工具权限继续适用。空结果正常。缺少 runtime、未安装此 Skill 或读取失败时继续主任务，并如实说明未加载；不自动初始化、绑定项目或创建空记忆。

## 条件触发

只有用户明确表达长期偏好、修订或撤销已有偏好，或出现有明确未来复用价值的协作纠正时，才激活 my-create-memory。阶段收尾只补查尚未处理的新证据；不为每个阶段例行生成总结或记忆。临时要求、团队事实、普通成功与失败、用户沉默均不触发。

## 并发委派

- 宿主支持子任务时，派发一个独立子任务执行 my-create-memory；主任务继续不依赖结果的工作。主 Agent 当场遵从用户纠正，不等待长期记忆生成。
- 传入项目路径、明确的个人库路径、当前场景、最少用户原话与必要上下文、可用来源/事件标识、已处理证据，以及可用 Skill 的真实路径。不要只传推断结论，不传完整对话或不必要的敏感资料。
- 同一会话只保持一个记忆抽取任务；有新证据时追加给已有任务，宿主不支持追加时待其完成再派发。相同证据不跨阶段重复派发。
- SDD 已作为其他子任务运行时，仅把用户偏好证据回传主 Agent，由主 Agent 统一委派记忆抽取。
- 子任务读取 Skill 后直接执行，不递归委派。只写个人记忆和必要项目身份绑定，不修改 SDD 产物、团队规则、业务代码或任务状态。
- 抽取可以并发，提交由 runtime 锁和 revision 校验保护。主 Agent 不同时手工编辑同一 memory.md。
- 回收新增、修订、候选、跳过与失败结果。最终只报告实际保存情况；无新增通常无需额外打断用户。
- 在本轮宿主生命周期结束前回收已承诺的抽取结果；不能假设子任务在会话退出后继续运行。未完成时明确未保存，不声称后台持久任务已建立。
- 宿主没有并发子任务能力时，在不影响主任务的阶段边界由主 Agent 独立执行，并注明顺序降级；用户明确要求独立子任务时不能静默降级。MVP 不创建常驻服务或自动扫描历史会话。
