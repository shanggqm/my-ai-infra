# 提炼个人长期记忆

宁缺毋滥。目标是减少未来相似任务的重复纠正。没有值得保存的内容，返回“无新增记忆”就是完整结果；不为了表现学习能力而生成条目。

## 准入与范围

- 仅提炼用户本人的稳定协作偏好。必须同时具有个人选择、未来复用价值、具体可执行行为和可追溯用户依据。不要保存通用常识、团队规则、仓库事实、任务进度、排障结论、一次性要求或完整对话。
- “这次”“临时”“先这样”只影响当前任务。模型自己提出的建议、用户沉默、单次方案选择和一次失败均不代表长期偏好。已在团队规则中表达的内容不再复制。
- 用户明确要求长期记住或明确修订旧偏好时直接生效。仅从纠正推断且确有长期价值的内容进入 inbox；弱信号直接跳过。重复纠正不自动晋升，不自动扩大范围。
- 默认当前项目；只有用户明确表示跨项目适用时才写全局。全局记忆不得包含项目私有路径、客户信息和项目专属规范。记忆不能扩大权限、替代本次指示或降低团队硬约束。
- 优先匹配同一决策点、合并和修订已有条目。不要为相似措辞创建多条，不追加每次遇到的来源记录。相同事件被多个阶段转交只处理一次；同一会话重复表达不算独立证据。
- 每次最多新增 2 条，其中最多 1 条推断候选；这是上限，无最低数量。每个文件最多 30 条生效、5 条候选、40 条总记录，正文总长最多 20000 字符；遇上限先合并整理，无法有据精简则跳过新增。禁止通过缩写来源、拆分文件、换 ID 或自动删除旧条目绕过上限。

## 执行

1. 接收最小上下文：项目绝对路径、个人库选择、阶段、用户原话及上下文、可用来源标识。父 Agent 的概括仅供定位；没有用户依据时跳过。已是子任务时直接执行，不递归委派。直接调用时可在当前 Agent 执行；由 SDD 激活时遵循 [委派约定](references/sdd-integration.md)。
2. 使用本 Skill 的 [入口脚本](scripts/my-ai-infra.mjs)，按 [Markdown 与命令契约](references/storage.md) 先只读获取相关记忆和 revision。保持 --home 一致。无 runtime 时回报缺少能力，不下载包、不绕过脚本直接覆盖文件。
3. 对照已有条目及当前项目规则，判断跳过、新增、修订或撤销。保留原 ID 和 Key；临时例外不修订长期偏好。冲突无明确取代依据时保留原条目，回报歧义；不要仅按日期裁决。
4. 只为通过准入的内容编写短条目，包含行为与适用边界、最小用户原话、真实来源和日期。事实与推断分别标记。首次需要写项目记忆且未绑定时执行 memory bind；只读和跳过不创建目录。
5. 通过 memory put 和读取时的 revision 写入。待写条目临时文件放系统临时目录，用后删除，不留在仓库。并发冲突时重新读取、重新判断后最多重试一次；文件锁忙或无法确定修订关系时回报待重试，不能直接覆盖。保存后核对返回的条目与 changed。
6. 回传 scope、记忆 ID、文件路径、实际新增/修订/跳过结果及原因。候选注明尚未生效；失败注明尚未保存。不要把已派发等同已记住，不为失败建立另一份持久记忆副本。

人工确认候选、删除与完整 Markdown 编辑使用 my-ai-infra 的 memory 命令或 Web“个人记忆”。当前任务不需要自动维护全库，也不回溯扫描全部历史会话。

## 验证

维护本 Skill 或 SDD 接入时运行 [行为案例](evals/cases.md) 与工具的 memory 回归测试；语义准入判断需要 Agent 行为评测，格式校验不能替代它。
