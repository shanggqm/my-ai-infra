# 原子阶段与场景编排契约

本文件定义阶段共用的输入、产物和交接规则；场景组合由 编排 Skill / 主编排者决定。资源从实际选中的安装作用域读取，不借另一作用域的同名文件补缺。

## 阶段职责与交接

调用交接至少说明当前任务/授权范围、有效来源与 AC、模板选择、已有产物及保留内容、路径、当前切片和相关依赖。只传实际存在且适用的文件，不要求填写固定参数表。

Skill 校验本阶段所需内容，产出自己负责的文档、代码或评审，返回：实际产物/来源、已执行检查与证据、阻塞或待验项、建议下一步。缺输入时交付可确定部分并回传缺口，不自行调用前后阶段或扩展授权。独立调用停在本能力；已有连续任务授权时由 编排 Skill 或主 Agent 编排后续、修复与复评。测试能力内部的执行委派保留，其他阶段仅回传测试缺口。

一个产物只有一个写入者。PRD/设计/评审/测试分别写自己的路径；评审不改规格或源码；实施不代写前序规格。必要变更交编排者安排对应能力，已有授权内常规接续无需重复确认。关键业务目标、权限语义、验收范围冲突交用户决定；其余独立工作继续。

## 有效需求来源与 AC

- 有有效 PRD 时，PRD 是需求与 AC 的唯一维护源；设计和测试引用编号。以实际内容/版本判断适用性。
- 无 PRD 时，设计至少需要目标、范围、预期行为、可判定验收及相关约束。读取 BRIEF、归档材料或当前会话；会话信息持久化到设计的“需求依据与验收”，记录来源。输入不足回传具体问题，不编造已确认规则或生成占位 PRD。
- 来源已有可维护 AC 时引用稳定位置/编号；只有素材时在设计建立规范化 AC。BRIEF 索引说明有效维护位置。后续实施、评审、测试使用这一来源，不因缺文件强推完整前置阶段。
- 后补 PRD：编排者安排 PRD Skill 迁入原 AC ID，再安排设计 Skill 保留技术内容、改为引用 PRD、把旧快照标历史，最后更新 BRIEF 的有效源。逐项复核任务、用例及受影响证据；中断时登记未同步部分，未完成迁移不宣称输入就绪。保留有效历史和人工批注。

## Profile 与模板

读取同作用域 [FEATURE_PROFILES.json](FEATURE_PROFILES.json)，以其键和 default 为合法值及默认值的唯一来源。缺失、损坏、未知值或相互冲突时报告资源/元数据问题，暂停依赖它的写入；不硬编码回退。首版 simple 表示简版规格，standard 表示标准规格；阶段数、风险、复杂度与 Phase 各自独立。

本次明确模板/档位 → BRIEF Profile → 注册表 default。旧 Feature 缺字段才采用 default。BRIEF 是 Feature 默认档位真源；目录名、编排 Skill 名称、ROADMAP 前缀不能覆盖它。单产物显式模板覆盖只记到产物，不改变 Feature 默认值。

1. 已有产物增量维护，保留有效内容和批注，不因档位变化整体重渲染。
2. 新产物先使用用户/项目明确指定的模板；不可读或与硬约束冲突时报告，不静默换用其他模板。
3. simple：项目 `mai-specs/_templates/simple/PRD.tmpl.md` 或 `TECH_DESIGN.tmpl.md` → 所属 Skill `assets/templates/PRD.simple.tmpl.md` 或 `TECH_DESIGN.simple.tmpl.md`。存在但损坏的项目覆盖必须报告；只有不存在才用 Skill 模板。
4. standard：沿用项目 `mai-specs/_templates/PRD.tmpl.md`、`TECH_DESIGN.tmpl.md`。模板缺失可交可确定草稿，说明缺口；simple 覆盖与随包资源都缺失时也不得声称按该模板完整交付。
5. 项目标准模板中有效的业务硬约束对 simple 仍适用；普通章节不强制搬入简版。
6. 新文档记录实际 Profile、模板位置、有效需求来源。旧模板的固定“PRD / PRD AC”字段在无 PRD 时填写已登记的实际需求来源/AC，在产物说明字段含义并使用真实链接；不修改用户模板，不制造 PRD。

产物路径遵守项目 `mai-specs/FEATURE_LAYOUT.json`；缺少时用随包默认。simple 与 standard 共用 artifact ID/path，不生成 PRD.simple.md 等平行有效产物。返回 BRIEF 和引用链接按实际输出位置计算，只在写产物时建目录。缺少未选阶段文件正常；显式路径校验某 artifact 仍需真实文件，路径通过不证明内容或验收通过。

## 索引同步与状态

创建 Skill 用脚本生成 draft 最小包；编号从全局池分配，目录始终 `NNN-slug`。创建后 Phase、阶段选择和最终交付判断归编排者；单阶段 Skill 只登记自身产物/任务及必要来源，不自行推进 ready/dev/review/done。

BRIEF 以短记录说明选了哪些阶段、理由、有效源与实际结果，不存整份 PRD/设计。阶段省略不等于阶段已通过。旧 dev/review/done 保留；重开有用户意图后按项目规则记录。

调整 Feature 默认档位由编排者在授权内定点维护：

1. 读取 BRIEF/ROADMAP 并保存原值和理由，以 ID **和实际 BRIEF 链接**唯一定位。未知/多个 Profile 或行归属不明时保留现场，不用索引猜值。
2. 写入前复读，与读取快照不同先重新核对，保留外部编辑；先改 BRIEF，再只改同 Feature 的索引展示。不改 ID、目录、Phase、历史模板记录。
3. 目标分区五列 `需求、标题、规格、优先级、说明` 写规格列；旧四列 `需求、标题、优先级、说明` 保持结构，在目标说明前添加或替换唯一明确的 `规格：simple；` / `规格：standard；` 前缀，保留正文。未知列、重复分区/行、前缀歧义时停止相关写入。
4. 新建/缺失分区用五列；其他分区可以四列，保留历史行、批注及换行。Phase 移动时按目标分区列形态重新渲染该行，不能直接搬不同列数的行。
5. 两文件不构成原子提交。BRIEF 已改而索引中断时明确“索引待同步”，恢复按有效 BRIEF 修正目标展示，不回滚外部编辑。最后复读二者一致才能报告同步成功。只读任务发现不一致只报告。

## 证据与风险

风险决定契约、设计/代码审查和正反例验证；复杂度决定依赖切片与最终集成；关键未知先澄清或限定探索。授权只到探索/设计时停在该范围。生产数据、权限、不可逆操作等风险扩大时，暂停受影响实现，同一 Feature 补契约与前置门槛，将受影响旧证据标待复查。

已有证据核对其输入与代码基线，结果分已执行通过/失败/未执行/受阻/待核验。阶段测试只支持当前切片；最终核对全部承诺和集成。必要条件未验证、测试失败或有效评审阻塞时不结项，不降低 AC。不把文档、工具启动、文件检查或静态关键词当作实际宿主行为通过。

## 部分安装

调用前确认本作用域 Skill、共享契约、注册表与所选模板可读；缺依赖返回准确路径、受影响阶段和可做部分，不伪造已安装入口、不手工绕过失败初始化。仅阶段能力可用且不依赖缺失资源的工作可继续。旧版本仍硬性要求前序文件或自动跨阶段时报告版本能力差异，由编排者安排同批更新；不通过占位规格满足旧入口。
