# 按方案实施代码

- **设计保真**：遵循当前有效设计及必要评审结论。实现细节自主决定，需求、契约或关键设计变更先让用户选择。
- **完整交付**：覆盖需求与设计要求的实现、集成和配套变更。
- **项目一致性**：遵循项目开发规范与编码风格，优先复用，保持 MVP 范围。

## 阶段契约

先读取本作用域的[共享阶段契约](../my-create-feature/references/stage-contracts.md)，核对有效需求来源、Profile、模板、产物路径和授权。一次调用只完成本阶段，返回实际产物、证据与缺口；后续调用、修复复评和全局 Phase / ROADMAP 由 Prompt 或主编排者安排。连续授权内主编排者继续推进，独立调用保持边界。

## 前置条件

- Feature 实施需有效技术方案、AC 和必要评审结论，无影响当前实施的阻断；微小、明确、可逆的直接任务可使用明确变更说明与验证条件，无需创建 Feature。仅缺可选 PRD/测试计划不强制补齐。
- `test/TEST_PLAN.md` 可选但推荐；缺少时按需求验收条件验证。

> 下文为默认路径，以项目 `mai-specs/FEATURE_LAYOUT.json` 为准。

## 个人偏好记忆

若已安装 my-create-memory，按[个人记忆接入约定](../my-create-memory/references/sdd-integration.md)在开始时读取当前场景的已生效偏好。只有明确长期偏好、修订或有复用价值的用户纠正才条件触发抽取；默认异步委派，主任务继续，同一证据不重复派发。已作为子任务运行时仅回传证据，由主 Agent 统一委派，不递归派发。无新证据不生成记忆；收尾核对实际落盘结果。

## 工作流

### Step 1：加载完整上下文

按以下语义读取项目规则与实际适用的文档（直接微小任务仅加载相应变更说明）：

1. 项目 README、开发规范及相关代码。
2. `BRIEF.md`、`context/_INDEX.md` 及关联需求资料。
3. 登记的有效需求与 AC：有有效 PRD 则读取；无 PRD 则读取设计中持久化的需求依据或实际引用。
4. `design/TECH_DESIGN.md` 及其引用的补充设计。
5. 已有 `review/design_review.md`、`test/TEST_PLAN.md`。

### Step 2：制定实现计划

1. 识别需要变更的文件和模块，包含必要的接入与配套工作。
2. 按模块依赖确定实现顺序，拆分可独立验证的任务。
3. 将任务关联到需求验收条件，沿用现有任务记录；简单改动可直接列出计划。

### Step 3：逐模块实现

每个模块按以下顺序完成：

1. 阅读对应设计，探索现有实现与复用方式。
2. 按设计编写代码，遵循项目技术栈、分层、命名和错误处理约定。
3. 完成调用链集成与必要配套变更，保留用户已有修改。
4. 记录实际变更、任务进度与未处理项。新增规则副本、临时例外或契约偏差时，记录原因与影响并回传设计同步；偿债限于已授权范围，不顺带改造无关模块。

> 遇到实质冲突或需要偏离已评审设计时，说明原因、影响和选项，暂停受影响部分；由编排者按已有授权安排设计能力先同步，再继续实施；仅涉及业务决定的实质选择需用户确认。本 Skill 不代写前序规格。

### Step 4：测试验证

1. 按测试计划或验收条件，验证核心流程、异常场景和相关边界。
2. 运行项目适用的格式、静态检查、构建和测试命令。
3. 修复问题并复验，记录实际结果；环境受阻和未验证项单独说明。

- 开发测试完成后，检查真实页面、跨模块链路及业务最终结果是否仍缺验证；实现改动使旧用例失效时，只更新相关范围。
- 发现业务测试缺口时，回传缺口、建议动作、依据和对交付的影响；由编排者决定是否调用 `my-create-test-plan`，本 Skill 不自行派发其他阶段。已有覆盖与安排不重复。
- 尚未取得必要验收结果时保留待验状态，可继续无关实现与代码评审准备；不能把 SubAgent 已启动当作测试通过。

### Step 5：自检

- [ ] 需求与设计要求已实现，必要集成与配套变更齐全。
- [ ] 实现符合已确认设计和项目编码规范。
- [ ] 无占位实现、调试残留或未说明的交付缺口。
- [ ] 验证结果有实际依据，未通过降低验收标准关闭问题。

### Step 6：更新进度

1. 更新已有实施任务记录，返回产物、证据和缺口；BRIEF Phase 与 ROADMAP 由编排者维护，不自行推进 dev 或 done。
2. 汇总实现范围、已确认的设计调整、验证结果和剩余问题。

## 下一步

- 有阻塞先解决；实现与自检完成后进入代码评审，`my-review-code` 可用时给出带实际 Feature 的调用请求。
- 已获连续阶段授权时由编排者继续执行；提交、推送与发布遵循已有授权。
