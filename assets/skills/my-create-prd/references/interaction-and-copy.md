# UI 对照、交互与文案

仅在当前需求涉及界面或用户可见/可访问文字时读取。沿用目标产品已有组件、术语、平台和可访问性规范，不假定产品品牌、设计工具或前端框架。

## 检查输入与选择产物

确认设计是否覆盖本次页面、流程和必要状态。Figma 等设计链接定位到页面/节点；记录已读取范围，未能访问时标记未核验。旧截图、空链接或仅有正常态属于部分覆盖；缺失部分形成可评审草案，保留假设。

新页面或布局/交互变化提供可视依据：沿用已覆盖的设计稿，或补内嵌线框、标注截图、可点击原型。可读且获准使用的图尽量内嵌，长设计附节点链接；仅文案变更可用精确位置/状态表。选择能消除歧义的最低成本方式，不固定要求 HTML、图片或 Figma。

多步骤、复杂布局或交互确需体验评审时，可用 coding 生成 HTML 高保真原型，沿用项目设计系统、组件与文案；遵循用户指定的形式。标明演示数据、模拟交互与未覆盖状态，检查入口可打开和相关交互可用。正文链接真实文件/入口，不将静态示意描述为已连接后端的功能。

## 对照设计描述功能

按页面/组件组织设计依据与功能对照表，定位区域或控件，明确新增/变更、原行为 → 本次行为及关联 FR；未改动区域可注明沿用。设计稿、截图和原型标明现状或拟议方案，缺覆盖的状态单列。布局、信息层级和操作路径应能从图与说明共同读懂。

## 最小交互契约

- 用户目标、入口、信息层级、主/次操作及离开/取消方式。
- 相关默认、加载、空、错误、成功、禁用与权限状态；不适用的状态可以说明理由。
- 提交、等待、重复操作、失败恢复和高风险确认；写清对象、范围、后果与可恢复性。
- 必要的键盘操作、焦点进入/返回、控件标签、图标可访问名称、屏幕或设备限制，沿用项目平台能力。

## 文案契约

为本次新增或修改的文字列触发位置、最终文案、状态变体和必要可访问名称，动态变量说明空值、数量、超长与格式语义。已确认文案逐字保留，包括标点和变量；修改建议单列，不自行润色。错误提示说明可执行恢复；按钮能预判动作；不以“友好提示”等占位文字代替可验收文本。

沿用产品现有称谓和术语；新拟文案避免重复标题、显而易见说明和无行动价值提示，已有文案的删改建议单列。风险、任务复杂度和使用频率决定详略；医疗、安全、金额、权限、隐私或不可逆后果的关键口径需有需求依据。缺少依据或意见冲突时让用户选择，不擅自定稿。

文案在 PRD 表格或独立资源文件中只维护一份，原型与验收引用同一契约。规格描述本次增量，链接既有产品真源，不复制整份设计系统；设计与文字冲突时明确指出，等待需求负责人决定。
