# 独立委派约定

## 监测与提醒

- PRD 梳理、技术设计及其评审、开发测试之后、代码评审时，主 Agent 结合当前资料检查业务验收缺口。已有覆盖充分、低风险改动或同一范围已在处理时，继续主任务，不重复规划、提醒或派发。
- 有缺口时用一句话说明建议动作、原因及是否影响当前交付判断，区分“梳理 / 更新用例”和“实际执行验收”。提醒可随进度或交付摘要给出，无需每次停下来询问。
- 用户已确认，或现有任务授权已覆盖所需工作时，主 Agent 可确定开展；默认使用独立 SubAgent。仅请求方案不授权浏览器验收；额外执行超出已有授权时只提醒，等待决定期间继续无关主任务。提醒本身不算同意。

## 委派与隔离

- 先确认 Skill 和 SubAgent 能力可用。复用宿主现有 SubAgent 机制，不要求安装专用角色；同一 Feature、同一范围已有测试子任务时先查询或更新该任务。
- 交接最小必要上下文：目标项目 / Feature、当前切片与变更基线（含相关未提交改动）、需求与已有计划路径、已知覆盖及待调查缺口、本次只规划或可执行的授权范围、产物路径与回传要求。预期来自原始需求，不预设应当通过。
- 子任务独立读取 Skill 和源资料，只写分配的测试计划、结果或隔离候选稿；不得借委派扩大权限、改业务标准、改生产实现或推进 Phase。遇到需要产品决定的问题回传主 Agent。
- 同一产物只指定一个写入者。主任务也需修改测试计划时，让 SubAgent 写隔离候选稿，由主 Agent 合并；输入变化后核对结果适用性，仅受影响部分重验。
- 实际执行使用可区分的测试环境、数据和浏览器会话；共享数据库、端口、账号或浏览器无法隔离时协调使用，不并发争用或清理主任务资源。不能安全并行时先做规划，将相关执行排到资源可用时。
- SubAgent 收到委派后直接完成任务，不再派同类子任务。测试执行环境或工具不支持下放时如实回报，可先独立完成规划，再由具备能力的执行者处理获授权操作。

## 主任务继续与结果回收

- 委派后主 Agent 继续不依赖结果的工作，不把测试流程变成每个阶段的必经等待。确实影响需求决策、合并或交付的必要证据未齐时，只保留对应阻塞或条件，不虚报通过。
- 子任务回传产物路径、覆盖范围、实际结果与证据、未验证项和需要主 Agent 决定的事项；主 Agent 核对基线、写入冲突和结论后汇总，不将启动成功当作完成。
- 收尾区分已完成、运行中、受阻和仅建议。对已承诺交付的测试子任务，在本轮可用的执行生命周期内回收结果；运行时不能跨轮保持任务时，不宣称退出后仍在后台执行。
- 宿主无 SubAgent 能力时明确说明：可由主 Agent 在独立步骤完成已授权且不干扰主任务的工作，或保留下一步请求。用户明确要求独立执行时，不静默降级为主 Agent 执行。
