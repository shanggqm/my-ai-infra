# 最小执行依赖

只规划时无需新增工具。执行时先检查当前会话实际可用能力，再补缺；项目测试库、运行时和原有测试命令沿用仓库约定，不在此维护框架清单。

## 最小配置

| 要完成的工作 | 必要能力 | 缺少时补什么 |
|---|---|---|
| 运行已有测试、检查后端业务结果 | 终端与项目现有运行环境、测试或服务入口 | 补齐项目文档规定的环境；无额外通用测试工具要求 |
| Web UI 与业务流程验收 | 一套能打开页面、操作、观察结果并截图的浏览器能力 | 优先启用宿主原生集成；确实没有时补一套 Playwright CLI 与可运行浏览器 |
| 原生桌面或跨应用流程 | Computer Use 或项目已有平台驱动 | 仅遇到该类场景再配置；普通 Web 验收不要求额外安装通用桌面控制 |

## 按宿主接入

- Codex：当前会话已有浏览器 / Computer Use 工具时直接复用。桌面内置浏览器与 CLI、IDE 的配置有区别，不能仅凭产品名推断能力。[官方浏览器说明](https://learn.chatgpt.com/docs/browser?surface=app)
- Claude Code：已有 Chrome 集成时复用；未接入且环境支持时，安装并登录 Claude in Chrome 扩展，通过 `claude --chrome` 或 `/chrome` 启用、检查连接。账号和平台支持以 [官方接入说明](https://code.claude.com/docs/en/chrome) 为准。
- 其他 CLI 或原生集成不可用：默认补 [Playwright CLI](https://github.com/microsoft/playwright-cli) 及其运行前提；已有可用浏览器 MCP 时直接复用，不重复安装两套。具体安装步骤读取官方文档和本机帮助，按项目版本约定执行。

安装和接入通常在开发环境初始化时完成。本 Skill 调用时只判断是否可用；需要安装但尚无授权时先列明缺少的那一项，不自动修改项目依赖或宿主配置。

## 就绪检查

- 执行前确认：应用可启动或目标地址可访问、测试账号与角色可用、初始数据能准备、操作后能清理。只记录凭据引用，不把秘密值放进计划。
- 浏览器能力只有成功打开目标并完成必要观察后，才能记录为已验证可用；工具已安装不等于连通。只做规划时不启动浏览器做这项检查。
- 用一句话记录“复用什么、是否可用、缺什么”。缺条件则保留待验用例并说明解阻方式，无需 CAP 编号、完整工具画像或独立能力清单。
