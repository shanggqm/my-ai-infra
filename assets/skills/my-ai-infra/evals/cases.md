# 入口 Skill 行为验收

自动回归在本仓库 `test/infra.test.mjs`，使用临时个人目录与项目，不修改真实配置。`test/quality.test.mjs` 还验证独立克隆与嵌入课程目录时都只读取 `assets/skills/`，外层同名 Skill 不会覆盖唯一源。

| 场景 | 应观察到的行为 |
|---|---|
| 用户要求将项目初始化为 Codex + Copilot | 生成两种适配，无 Claude Code 或 Cursor 副本 |
| 已有项目明确偏好 | 沿用配置，重复安装无需变更 |
| 同名未受管 Skill | 预览标出冲突，应用失败，原文件保留 |
| 用户只要求检查 | plan / doctor 只读，不创建个人源或项目文件 |
| npx 缓存已清理 | setup 安装的全局入口继续调用个人 runtime |
| 目标项目已更改 Skill 副本 | 同步拒绝覆盖并报告文件 |
| 用户要求打开 Web | 本地链接可读取配置，保存使用预览版本检查 |
| 旧版 Skill 名出现在配置中 | 只读预览解析到 canonical 名，应用后以新名安装 |
| 个人资产库仍使用旧目录 | 迁移时保留正文修改、附属文件与恢复备份；双名并存时报告冲突 |
| 配置仍使用 my-create-code | 以 my-implement-code 安装内置版本，历史个人正文与附件完整备份；四种工具只安装一份 canonical 副本 |
| 稳定 runtime 留有旧版包目录 | 更新时把旧名包移至备份，wrapper 的 catalog 不出现双名冲突 |
| 新库选择未知 Skill 或已移除的旧别名 | 返回 Unknown Skill，不写入配置；新库仅提供 9 个内置项和 7 个默认项 |
| 使用 --home=PATH | wrapper 与 CLI 都解析同一个个人目录，不读取环境变量指定的其他库 |
| 用户要求升级个人基础设施 | 内置 Skill 跟随发行版本，旧受管副本完整备份迁移，未知来源同名冲突保持原状，个人 Skill 和项目副本保留；显式 plan/sync 后才更新选定项目 |
| 显式 home 与环境变量冲突 | 包内/项目 wrapper 优先从显式 home 读取 runtime 与资产，不触碰环境库 |
| home 相对路径、重复参数或缺值 | 相对路径从调用目录解析，重复值沿用 CLI 的最后值；缺值在导入前报错，不写文件 |
| setup 生成的全局 wrapper | 稳定 runtime 仍绑定安装位置，不被无关环境变量误导 |

人工对话复核：用户已授权初始化时，Skill 的步骤应持续执行到 doctor；用户只要求查看时应停留在只读操作。自动测试验证 CLI 和 wrapper 执行结果，不等价于模型对话评测。

## 独立验收 Skill 移除回归

- 新建个人库、项目与实际发布包均不包含 `my-verify-feature`，新路径契约不声明 acceptance 产物。
- 旧默认和项目偏好含该项时，预览只读，应用后剔除；四种工具下未修改的受管副本移除，已有验收报告与自定义路径契约保留。
- 修改过的受管副本阻止同步；个人库保留旧文件但不再列入可选目录，也不允许以退役名重新导入或编辑。
- 仅选择该项的旧配置显示为空，可通过 CLI 或 Web 重新选择；未选择替代项前不执行同步，不自动扩展安装范围。

## assets 统一管理回归

- 包、个人库、项目和全局源分别位于 assets/、个人库 assets/、.agents/；Codex Skill 为源文件，Claude Code Skill 以及各工具 Agent 入口为相对链接。
- Agent 中立源修改后 sync 更新全部派生格式；原生文件修改受冲突保护。
- 旧个人库、项目 Skill、Agent 和规则迁移保留正文、基线与备份，plan 只读。
- Prompt 通过单个 Markdown 文件导入，以文件名与 frontmatter 描述识别，四种工具入口均链接到 `.agents/prompts/<名称>.md`；编辑、重复同步、移动、升级与旧清单兼容通过回归，新旧同名冲突及无效描述不覆盖原文。
- Hook、MCP 及未预置的新类型使用同一清单、导入、编辑、计划、冲突与移除机制；非法目标与过期编辑拒绝。
- 运行包内 test/assets.test.mjs 和既有冲突、Agent、single-source 回归；测试仅验证装配，宿主执行能力依各工具的配置。

## 个人记忆回归

- 选择自定义 --home 时，记忆读取、写入和委派始终使用同一库。
- 无新偏好不创建空 memory.md；项目初始化不生成偏好。
- 全局 setup 选中 my-create-memory 时安装稳定 wrapper；取消或未选时不擅自启用抽取。
- 记忆不进入资产分发；项目 ID 在同步后保持，迁移路径后仍能定位。
- 新偏好统一交给 my-create-memory；弱信号跳过，推断不自动生效。

## 内置与个人 Skill 分离回归

- 用户要求更新内置 Skill 时说明只读边界；需要跨项目复用时使用新名称导入个人 Skill，不反向覆盖内置源。
- catalog / Web 依据内置登记与实际目录返回 origin，不能通过 frontmatter 伪装来源。类别保持独立。
- 个人 Skill 完整导入，重名拒绝；新项目默认发现新增项，显式默认清单与已有项目选择保持。
- CLI 与 HTTP 均拒绝修改内置 Skill；Web 内置正文只读且保存按钮禁用，个人新建/编辑可用。
- 升级旧内置副本时正文与附属文件原样备份，未知来源同名目录保持原状并报错；runtime 按完整目录更新，已删除内置文件不再补回。
- npm 全局卸载和重装保留个人库，重新初始化能安装个人 Skill 及附件；不操作真实用户配置。
