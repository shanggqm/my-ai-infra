针对本次需求，使用原子 Skill 组合完成已授权范围，默认新 Feature 为 simple。先读取当前作用域 my-create-feature 的 `references/stage-contracts.md` 与 `references/FEATURE_PROFILES.json`、项目规则和已有上下文；其他能力也从同作用域读取。缺资源明确返回受影响阶段及路径，不借另一作用域或占位文档补缺。

依据风险、复杂度和输入充分性，用一句话说明阶段选择，并在实际 Feature 的 BRIEF 留下简短理由、有效需求/AC 来源和实际状态：

- 明确、可逆、无新增业务规则的微小改动：直接实施与针对性检查；未要求建包时不创建 Feature，遵守项目评审要求。
- 功能级 Demo 的目标、范围、行为、AC 和约束充分：创建或复用 Feature → my-create-design（simple 模板）→ my-implement-code → my-review-code → 实际验收。设计持久化需求依据/AC，可省略独立 PRD。
- 产品旅程、范围或规则需要整理：先 my-create-prd（simple 模板），再独立技术方案与后续实施。真正影响目标/权限的未知回传用户决定，不能把假设当确认。
- 已有有效方案：核对适用范围、必要门槛后复用；不因入口或档位变化重做文档。
- 技术或业务方向未知：先限定探索问题、方法和退出标准，依据证据重新组合；仅授权探索就停在探索。
- 低风险多模块任务：保持 simple，设计拆依赖、阶段准入/退出条件，逐段实施验证并完成最终集成；一阶段通过不代表整体通过。
- 出现权限、生产数据、不可逆操作等高风险：先补必要契约，由 my-review-design 审查并安排修复复评；实施后 my-review-code 与修复复评，验证必要正例/反例。实施中风险升级暂停受影响代码，同一 Feature 接续、旧证据复核，不按文件数判风险。

设计审查和独立测试计划按实际不确定性、风险及项目要求调用。低风险功能仍保留代码评审和真实验收；AC/现有测试不足以指导验收时调用 my-create-test-plan。测试能力内的独立委派遵守其约定，当前编排者回收证据与缺口并安排相应能力修复，避免重复调度。

阶段间交接本次相关的债务证据与待决取舍，沿当前变更修正、复评；独立存量分析仅在明确请求或已有授权编排内安排，不作为固定阶段。偿债经当前验证后，在授权内更新有效约束、契约和回归入口；历史规格保留，团队债务不写入个人偏好记忆。

新建时向 my-create-feature 传 profile；旧 Feature 的有效 BRIEF Profile 优先，缺字段用注册表 default。单产物模板覆盖只写入产物；改变 Feature 默认值时按共享契约定点同步 BRIEF 与 ROADMAP，保持 ID/目录，保护批注及外部编辑，中断报告索引待同步；最后复读一致再报告成功。已有文档增量维护，simple 与 standard 共用 layout 路径。后补 PRD 保留 AC ID 并安排有效源迁移与证据复查。

当前 Skill / 主 Agent 负责后续调度、阶段状态和修复闭环。独立 Skill 只完成当前能力。显式完整 SDD 优先遵守，单阶段/仅设计请求停在授权范围；常规接续在已有授权内推进，真实业务决策冲突再询问。状态按实际内容、门槛和项目定义推进；Phase 跨索引分区时按目标表头渲染。必要测试失败、评审阻塞或承诺证据缺失时保留未完成，不降低 AC，不把计划、路径检查或静态检查当实际验收。全部承诺及集成有当前证据后再按项目规则结项；提交、推送与发布遵循已有授权。
