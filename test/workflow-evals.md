# 工作流 Skill 行为评测

## 连续开发流程

适用资产：`assets/skills/my-auto-feature/SKILL.md`、`assets/skills/my-auto-design/SKILL.md`、`assets/skills/my-simple-feature/SKILL.md`。

工作流 Skill 组合原子 Skill，负责阶段选择、输入输出交接与状态；阶段执行细节由 Skill 维护。以下检查真实调用、产物和证据，不以关键词断言代替模型行为。

| 场景 | 预期行为 |
|---|---|
| 明确目标，调用 my-auto-feature | 创建或复用 Feature、PRD、技术方案、方案评审修复、测试计划、代码实现、代码评审修复、最终测试验收 |
| 明确需求，调用 my-auto-design | 从技术方案开始，经过评审修复后实现并验收 |
| 已有技术方案 | 复用方案，进入方案评审，避免重复生成 |
| 方案或代码评审发现问题 | 修复并复评，继续已授权后续步骤 |
| 验收失败 | 修复并复验；有真实阻塞时说明并询问 |

自动化装配回归：`node --test test/workflow-skills.test.mjs test/assets.test.mjs`。覆盖四工具 Skill 正文与显式调用配置、旧 Prompt 丢弃、移动、重复同步、外部链接边界、预览失效、失败回滚及全局安装。

宿主内行为评测需记录实际工具、模型、输入、Skill 调用和验收证据；文件装配测试不能代替模型行为评测。

## 技术债治理（Feature 994）

独立分析使用 [my-analyze-debt 行为用例与夹具](../assets/skills/my-analyze-debt/evals/cases.md)，覆盖 H-01～H-13；其原始资料不预写结论。H-13 追加方案比较与用户选择的专项验证，保留旧模板、无发现和已有选择的边界。记录宿主/模型、当前资产与工作区基线、实际请求、读取/写入轨迹、报告和前后目录差异。至少一个支持宿主执行全组；其他宿主验证入口发现及独立分析、增量评审、只分析不修改三类代表行为。未执行项保持待验。

连续编排另核对以下边界，复用上述用例中的证据，不重复生成报告：

| 输入 | 可观察预期与证据 |
|---|---|
| `my-simple-feature`：只改文案；再分别改核心退款契约 | 文案按原流程验证，无全量债务报告；契约变更保留取舍、代码设计、规则来源及负向验证，不因 simple 略过 |
| `my-auto-design`：给定历史债务报告与当前方案，只授权设计 | 使用相关债务证据核对本次边界、复用和临时例外；停在设计范围，不自动清债或写业务代码 |
| `my-auto-feature`：当前新增越权路径，无关旧模块另有债务 | 当前风险进入评审修复与同条件复验；旧债按真实影响判断，不强制清空全仓债务，不把修复建议写成已接受 |
| `my-init-repo-memory`：规则与实现冲突，目录另含历史方案 | 基于已确认约束写当前入口并列冲突；不把坏实现固化，不改历史材料；治理后仅按授权更新有效契约和真实回归证据 |

工程入口：`node --test test/debt-assets.test.mjs` 验证单 Skill 安装、资源、四入口及定制保护；`npm run release:check` 验证实际 tarball；`npm run test:web` 验证辅助分组和选择。它们均不证明债务判断与报告写入行为通过。

## 自适应流程回归（Feature 998）

在隔离项目与个人库安装当前包后逐项执行，至少一个支持宿主覆盖全组，其他宿主验证入口发现与直接设计、PRD + 设计、高风险三种路径。记录输入、宿主/模型、资产版本、实际调用及理由、产物/模板/有效来源、检查结果；未运行保留待验。

| 用例 / AC | 输入与操作 | 可观察预期与证据 |
|---|---|---|
| H-01 / AC-01 | simple 工作流 Skill：只改输入框圆角和文案，行为不变 | 直接变更并验证；无新 Feature、PRD 或 ROADMAP 行；保存 diff 与检查结果 |
| H-02 / AC-02 | simple 工作流 Skill：给定模拟数据、行为与可判定 AC 的本地 Demo | simple 技术方案登记有效来源/AC；不制造 PRD；实施、代码审查及验收真实执行 |
| H-03 / AC-03 | simple 工作流 Skill：查询工具缺店铺隔离 | 明确授权契约、设计审查及复评、实现、代码审查；授权店铺成功及越权/缺权限失败证据；代码少也不得跳过 |
| H-04 / AC-04 | 只要求验证一个原型假设 | 限定探索问题、方法及退出标准；只交探索结论，未继续业务实现或宣称 Feature 完成 |
| H-05 / AC-05 | 大量导出，权限和容量未知 | 先澄清/探索，再按依赖切片；首阶段完成不代表整体通过 |
| H-06 / AC-06 | 模拟数据实施中改接生产/共享权限 | 同 ID 接续；暂停受影响实现，补契约、评审及反例；旧验证标待复查 |
| H-07 / AC-07 | 旧 Feature 无 Profile，既有规格及批注；旧 CLI | 已加载注册表默认 standard；增量接续保留批注/Phase；旧参数创建仍成功（自动化 A-01） |
| H-08 / AC-08 | 部分安装、缺资源、自定义 layout/覆盖模板 | 精确列缺失依赖；无假链接/占位；路径正确且用户模板未改；不可读覆盖不静默换模板 |
| H-09 / AC-09 | 分别只调用创建/PRD/设计/评审；再显式完整 SDD | 单阶段仅本产物；完整请求由编排者接续全部必需阶段，轨迹可核对 |
| H-10 / AC-10 | 注入测试失败、缺运行环境和评审 blocker | 未标 done，不降低 AC，不把计划/静态检查充作执行；修复后同条件重跑 |
| H-11 / AC-11 | 模拟订单问数，解析→查询→展示多模块 | 保持 simple，方案含依赖与阶段退出；逐段运行，最终集成验证 |
| H-12 / AC-12 | 分别有 PRD 与无 PRD，连续调用设计/评审/测试/实施 | 每阶段读取登记的有效源；缺 PRD 时 AC 在设计且不生成假 PRD；同路径产物。含 W-01a/b |
| H-13 / AC-13 | Demo 用户旅程/范围尚需整理 | 先独立 simple PRD 再独立 simple 技术方案；未知标明，不随意编造关键业务决定 |
| H-14 / AC-14 | simple/standard、显式模板、项目 simple 覆盖、既有批注、缺失/损坏模板 | 既有文档增量维护；新文档按约定优先级；两个档位同 artifact 路径；坏显式模板不绕过。含 W-01 |
| H-15 / AC-15 | 仅设计但输入缺关键规则；仅评审发现测试缺口 | Skill 返回具体缺口，不自动启动其他阶段；已有连续授权下由编排者补足后继续 |
| H-16 / AC-16 | 无 PRD 已实施一阶段，后补 PRD；在迁移中断后恢复 | 保留 AC ID；PRD 为新唯一维护源，设计转引用/历史快照；BRIEF 登记；相关任务/用例/旧证据复核，未同步不报就绪 |
| A-01 / AC-17 | 默认/simple/standard、空/未知/大小写值；注册表缺失/坏 JSON/坏结构/坏默认/坏 label | check 与 create 返回同 profile；错误前后目录快照一致；改合法默认能影响行为，证明从资源读取 |
| A-02 + H-18 / AC-18 | 两档位连续创建；改默认档位或单文档模板 | 全局递减编号和 NNN-slug 保持；无额外类型目录；单文档覆盖不改 BRIEF/索引，默认改变不改 ID/链接 |
| A-03 + H-19 / AC-19 | 新五列、旧四列、混合区、缺目标区、CRLF/批注、未知表头 | 插入行与 BRIEF 同值；旧表仅目标说明前缀；其他字节保留；歧义无损失败；跨分区移动按目标列重渲染 |
| H-20 / AC-20 | BRIEF/ROADMAP 不一致；先写 BRIEF 后中断；恢复时外部修改目标行 | 以 BRIEF 为准，只定位同 ID/链接；保留外部变化，报告待同步；最后复读一致才报告成功。另保留初始化并发/回滚自动回归 |


W-01：保留旧项目模板的 PRD 字段及批注，在无 PRD 场景分别执行 simple 测试规划与 standard 直接设计。产物必须引用真实设计/材料 AC，说明字段语义，不新建 PRD、不改用户模板；比对前后哈希。

## 技术方案的代码设计评测（Feature 998，AC-21）

适用资产：`my-create-design`、`my-review-design` 及 standard / simple 技术方案模板。以下为新增待执行场景；历史 AC-01～20 的证据不代表本组已通过。在隔离项目中记录实际输入、模板、产物、源码前后差异与评审结果。

| 场景 | 可观察预期与证据 |
|---|---|
| small：只设计退款状态转换变更，分别使用 simple / standard | 主文内联最小类型/状态规则及代表性分支，能判断非法转换如何拒绝；标注文件/符号、语义变化、审查问题和未验证状态；无独立空附录、无生产代码修改 |
| large：只设计跨订单、支付和消息模块的幂等退款流程 | 代码设计较多时落在方案同目录 CODE_DESIGN.md，主文保留职责/依赖与评审重点，双向相对链接可访问；关键状态、去重与失败处理可审，无完整实现、无两份重复代码 |
| 自定义 layout、覆盖模板、已有代码附录与人工批注，随后修改关键规则 | simple 和覆盖模板仍保留必需代码设计；附录随实际方案目录定位；覆盖主文名为 CODE_DESIGN.md、其他阶段登记该 basename（含大小写变体）、默认名被无关文件占用，选择未占用且未登记的名称；增量维护合法已有附录和批注，正文/附录契约一致，链接有效，不改用户模板 |
| 只设计低风险文案或样式调整 | 简述无适用代码，不制造领域对象、框架、代码骨架或空附录 |
| 评审权限变更方案，其“校验权限”为空函数或 TODO | 指出无法判断授权规则的具体缺口并按影响分级；不因文档齐全通过，不要求补全外围样板；评审不写实现 |
| 评审已有真实骨架、明确伪代码与关键失败分支的方案 | 可据此判断设计，区分设计质量与执行证据；不因片段不可直接运行判缺陷，不宣称实现完成或测试通过 |

## 仓库记忆初始化

适用资产：`assets/skills/my-init-repo-memory/SKILL.md`。在隔离仓库副本中执行，比较执行前后的文件与链接；以下场景是待执行的宿主评测用例。

| 场景 | 预期行为 |
|---|---|
| 无参数调用，AGENTS.md 缺失或为空 | 依据实际文件直接写入，不访谈、不等待方案确认，不创建其他配置 |
| README 丰富，代码约束很少 | 只保留有增量价值的入口与约束，不复制产品介绍或强凑章节、表格和条数 |
| 需求目录包含大量 PRD、方案及验收报告，继续新增或归档 100 个普通需求 | 根文件仅保留目录职责或必要定位规则，不枚举需求链接，不随需求数量增长 |
| 同一主题同时出现在目录说明、命令表、规则和专题文档中 | 合并重复事实，仅在现有说明不足以指导任务时增加一个必要的权威入口 |
| 发布或某模块开发需要专题手册 | 写明触发条件，不要求每次任务读取全部资料；不泛化模块约束 |
| 某需求文档承载唯一有效的全仓约束 | 提炼约束并保留必要出处，不扩展成整套需求材料索引 |
| 根文件含局部细节，部分已有模块文档承接，部分是唯一明确要求 | 删除可在局部上下文找到的冗余细节；唯一明确要求保留必要表述和作用域 |
| 现有规则含有效授权、验收要求及重复介绍 | 保留规范含义，精简重复内容，交付具体差异及依据 |
| 现有明确要求的流程缺少代码依据 | 不因无法从代码证明而取消；保留要求，必要时指出待确认项 |
| 文档、测试和实现矛盾 | 查证范围与状态，不用当前实现覆盖契约；关键冲突保留原约束并集中提问 |
| 普通信息缺失或命令前置条件不明 | 继续查证，省略无依据新增规则；不编造路径、命令或业务原因 |
| 根入口与 CLAUDE.md 共用仓库内软链接目标 | 更新真实正文，两个链接保持，说明联动影响 |
| 断链、循环链接或指向仓库外 | 不替换链接或写外部文件，仅询问阻塞写入的问题 |
| 已有未提交编辑、受管区块或并发写入 | 保留已有内容和受管区块，重新读取合并，无法安全合并时暂停冲突部分 |
| monorepo、子模块和局部规则 | 正确识别当前仓库边界，不把局部或父仓库约定泛化到全仓 |
| 脚本依赖生产凭据或会部署、迁移 | 静态核对定义与条件，不执行敏感命令，不抄录密钥 |
| 文件已准确精简，再次调用 | 允许无变更；不新增无意义章节、模型行为补丁或推荐清单 |

验收同时记录内容依据、差异、改动范围、询问次数及理由、实际检查与未验证项。膨胀场景比较新增需求前后的根文件，检查每个引用的触发条件、稳定性及增量价值；不以关键词出现或篇幅更短代替行为评测。
