# PRD：按风险与不确定性裁剪 SDD 流程

> Feature：998 | 状态：草案，待方案评审 | 日期：2026-10-16

[返回需求简报](../BRIEF.md)

## 1. 背景与目标（Why）

当前 `my-auto-feature` 固定串行调用创建需求、PRD、设计、两次评审、测试规划和实现。模板允许缩短内容，但阶段之间仍依赖多份文档，中小需求需要承担完整流程的上下文维护成本。

用户要求微小改动可直接完成，中小需求使用简化 SDD，高风险需求保留必要约束。用户提供的[流程裁剪示意](../context/需求来源与流程裁剪示意.md)进一步区分失败代价与关键决策不确定性。本 PRD 将其转为拟议产品行为，技术取舍见技术方案，尚未代表实现或用户批准。

目标：用户只描述任务，脚手架给出有理由的最小流程，能在获得新信息后升级；简化后的需求仍能从目标追踪到实际验证结果。

成功口径：微小改动不创建规格目录；典型中小需求通过一份业务规格完成实现与验收；高风险反例与关键证据不会因改动小而被省略；旧 Feature 可继续使用。

## 2. 用户与场景（Who / When）

| ID | 目标用户与触发场景 | 用户故事 | 关联需求 |
|---|---|---|---|
| US-01 | 开发者修改已确认的按钮文案或局部小 bug | 直接完成并报告针对性检查 | FR-01 |
| US-02 | 开发者为现有列表新增简单筛选 | 用短规格对齐行为，连续实现并验证 | FR-02、FR-07 |
| US-03 | 开发者修复订单查询租户隔离 | 明确权限不变量并验证越权路径 | FR-03 |
| US-04 | 产品/开发者尚未确定导出入口 | 比较可撤销的原型，收敛问题后决定实施 | FR-04 |
| US-05 | 开发者实现百万行异步导出 | 先验证容量、授权与失败恢复，再分段交付 | FR-05 |
| US-06 | 已有 Feature 的维护者 | 继续使用原规格、批注和验收记录 | FR-06 |

## 3. 总体业务流程

读取任务、当前代码和已有规格 → 判断失败代价、关键未知及影响范围 → 说明所选流程与理由 → 执行当前授权范围 → 新证据改变判断时重新分流 → 核对所有本次承诺的验证结果。

流程选择无需增加固定确认轮次。能够从代码或上下文判断的事项直接判断；影响目标、权限或验收标准的业务歧义需要用户决定。用户仅要求创建、设计或探索时，交付停在对应范围。

## 4. 功能需求（What）

### 4.1 新增需求

| 编号 | 触发条件/输入 | 预期行为 | 可观察结果 |
|---|---|---|---|
| FR-01 | 目标和改法明确、影响局部且可逆的低风险微小任务 | 直接修改，执行必要检查；遇到真实业务行为变化重新判断 | 不创建 Feature、ROADMAP 项或 spec；答复包含改动与证据 |
| FR-02 | 低风险、关键决策明确、可在一个紧凑闭环内说明的中小需求 | 创建或复用 Feature，以一份精简规格维护目标、边界、改法、验收、结果 | 无需独立 PRD、技术方案、测试计划和评审报告即可完成 |
| FR-03 | 权限隔离、敏感数据、资金、不可逆数据变更等存在高失败代价 | 先明确相关契约、不变量和负向验收；实施前评审，实施后评审并验证 | 即使只改一行，也保留关键契约、反例和评审证据；文档可短 |
| FR-04 | 用户目标、入口、方案可行性等关键决定缺少证据 | 明确一个探索问题、方法、完成标准与产物，限定为可撤销验证 | 原型/探针结果可复查；探索完成不宣称业务功能完成 |
| FR-05 | 高风险且关键决策不确定，或有依赖的复杂交付 | 先验证关键假设，将实现拆成有准入、退出证据的切片 | 当前切片通过后才推进依赖它的切片；局部通过不等于总体完成 |
| FR-07 | 用户以轻量快捷入口表达任务 | 提供 `my-simple-feature` 入口并进行同一风险判断 | 简单任务可直接完成或走精简规格，风险扩大时转接必要流程 |

### 4.2 变更需求

| 编号 | 当前行为 | 目标行为 | 关联需求 |
|---|---|---|---|
| FR-06 | 完整流程和阶段 Skill 普遍预设独立阶段文档 | 自动入口支持分流；阶段 Skill 识别精简规格及已有完整规格；既有 Feature 默认保留原流程 | FR-01～FR-05 |
| FR-08 | 文档路径校验与评审已有边界，但没有统一裁剪契约 | 各入口遵循同一分流、升级、评审和验收规则；路径检查继续只判断路径 | FR-02～FR-06 |

## 5. 使用交互

本次涉及 Skill/Prompt 文案与调用行为，无新增 Web 页面。沿用既有自然语言任务输入和生成的工具入口。

建议在开始时用一句话报告：“按精简 SDD 推进：沿用现有筛选与权限，仅扩展负责人筛选；目标、改法和验收集中在 BRIEF。”风险或不确定性发生变化时，再说明升级原因和当前未完成事项。

`my-simple-feature` 是拟新增 Prompt 名称，当前环境尚不可调用。示例不构成要求用户记忆多种流程指令；`my-auto-feature` 同样自动选择合适路径。用户显式指定完整 SDD 时保持完整路径。

## 6. 业务规则与约束（Rules）

| 编号 | 规则 | 关联需求 |
|---|---|---|
| BR-01 | 先判断失败代价，再判断关键未知；复杂度决定规格是否需要拆分，不用代码行数、预计耗时或文件数代替风险判断 | 全部 |
| BR-02 | 风险或关键未知未判断清楚时不进入直接开发；先读取证据或探索，不把未知记为低风险 | FR-01、FR-04 |
| BR-03 | 直接开发适用于无新增业务规则、无关键契约变化的微小任务。跨租户 bug、数据库迁移等即使局部也有额外质量门槛 | FR-01、FR-03 |
| BR-04 | 精简规格至少包含目标与边界、预期行为、必要技术改法、可判定验收、实际结果；高风险额外保留相关不变量、反例、恢复方案与评审 | FR-02、FR-03 |
| BR-05 | 流程升级保留 Feature ID、现有内容、人工批注与已有证据；升级后新增承诺及受影响验收重新验证，不自动把历史通过结果沿用为当前通过 | FR-05、FR-06 |
| BR-06 | 既有项目明确的评审、测试、审批要求是下限。用户授权连续推进时不重复询问；新增流程不会扩展为提交、发布或生产操作授权 | 全部 |
| BR-07 | 完成要求本次承诺均有当前有效证据；计划完成、文档齐全、路径通过、探索成功、子任务启动均不构成交付通过 | 全部 |
| BR-08 | 显式调用创建需求仍创建最小 Feature；只有未要求建包的微小任务可走无规格路径。显式指定阶段只完成其范围 | FR-01、FR-06 |

不新增运行时依赖、评分系统、工作流数据库或固定人工审批。资源装配沿用现有唯一源、同步冲突与路径安全规则。

## 7. 范围与边界（Scope）

包含：流程规则、精简规格载体、创建参数与模板、现有七个 SDD Skill 的阶段兼容、两条自动 Prompt 的分流、轻量 Prompt、升级与证据规则、自动回归和宿主行为评测方案。

不包含：自动发布、远程审批系统、Web 流程编辑器、通用工作流引擎、评分模型、自动改写历史 Feature、自动替换用户自定义 Skill/模板。

依赖：目标项目可读取，所需 Skill 可用；高风险或探索所需环境由实际任务决定，缺失时只推进不依赖它的部分。

## 9. 验收标准（Acceptance Criteria）

| ID | Given / When | Then | 验证方式 |
|---|---|---|---|
| AC-01 | 已确认按钮文字且行为不变；通过轻量或自动入口提出修改 | 不生成 mai-specs/Feature 或 ROADMAP 项；完成变更并报告针对性检查 | 宿主实际运行，比较前后文件和调用轨迹 |
| AC-02 | 现有列表新增负责人筛选，沿用权限和分页且语义明确 | 建一个 Feature；BRIEF 独立承载目标、改法、验收与结果；不强制生成其他阶段文档；验证空结果与清除筛选等相关行为 | 初始化回归 + 宿主完整交付 |
| AC-03 | 只需局部改动的订单跨租户访问修复 | 判为高风险；先写身份来源、资源归属及拒绝策略，评审后实现，验证越权与合法访问，再评审 | 宿主行为评测与相关反例证据 |
| AC-04 | 用户仅要求比较两种导出入口原型 | 记录问题和判断标准，产出模拟原型/观察，停在已授权探索范围；功能验收保持未完成 | 宿主行为评测 |
| AC-05 | 百万行异步导出且容量/授权语义未确认 | 先验证关键假设；每个依赖切片有进入与退出证据；首片成功时 Feature 不得 done | 宿主分阶段评测 |
| AC-06 | 精简需求实施中发现共享权限或数据迁移影响 | 暂停受影响实施，记录新风险并补必要契约/评审；升级复用同一 ID，旧证据有影响则标待复验 | 宿主行为评测 |
| AC-07 | 旧 Feature 无流程字段、有独立 PRD/设计及人工批注 | 按原完整流程接续，保留全部文档与 Phase；旧 CLI 创建命令仍可用 | 兼容回归 + 宿主恢复场景 |
| AC-08 | 只安装部分 Skill，或使用自定义布局/已有模板 | 可读规则与路径优先级明确；缺必要能力时列出缺口，不伪造调用；不覆盖已有文件 | 隔离装配回归 + 宿主缺依赖场景 |
| AC-09 | 调用 `my-create-feature` 或用户显式要求完整 SDD | 前者建立最小包；后者沿用完整规格。创建和设计不会自行实施 | 初始化回归 + 宿主授权边界场景 |
| AC-10 | 测试失败、关键场景未测或存在未解决评审阻塞 | 不报告完成；列明失败/待验项。精简路径保持相同证据要求 | 宿主失败与误报场景 |
| AC-11 | 风险未知或低风险但多模块依赖复杂 | 未知先核实；复杂闭环使用标准规格或分片，即使没有安全风险也不会强压成微小任务 | 宿主边界评测 |
| AC-12 | 在精简 Feature 中分别调用 PRD、设计、测试和评审 Skill | 更新同一有效规格或对应必要报告；阶段能够正确接续，不因缺独立 PRD/设计而阻塞或补空文件 | 宿主逐阶段调用 |

## 待确认事项

无阻塞创建和方案编写的业务缺项。流程字段、精简载体、共用规则位置及升级方式属于技术方案建议，交方案评审判断；当前不标记为用户已批准。
