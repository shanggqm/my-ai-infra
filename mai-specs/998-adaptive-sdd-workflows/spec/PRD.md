# PRD：原子 Skill 与场景 Prompt 的自适应 SDD 流程

> Feature：998 | 状态：草案，待方案评审 | 更新：2026-10-17

[返回需求简报](../BRIEF.md)

## 1. 背景与目标（Why）

当前 `my-auto-feature` 固定串行调用创建需求、PRD、设计、两次评审、测试规划和实现。阶段模板可以缩短，但 Skill 输入仍普遍要求前序文档，场景编排与单阶段职责有交叉。

用户明确采用“原子 Skill + 场景 Prompt”的组织方式：Skill 独立完成一类任务，Prompt 组合适合场景的调用路径。simple 需求可以生成简版 PRD、技术方案，由模型依据已有输入选择阶段。具体来源见[本轮需求澄清](../context/2026-10-17-原子能力与场景编排.md)。

目标：复用现有阶段能力，让微小修改、简单 Demo、复杂模拟链路和高风险需求各有合适的阶段组合；输入输出保持可接续，验收仍有实际证据。

成功口径：需求充分的 simple Demo 可从技术方案开始；需要梳理产品行为的 Demo 可先 PRD 再设计；两条路径使用同一组 Skill 和相应模板。高复杂度低风险任务支持分阶段 simple 交付；旧 Feature、项目定制及质量约束继续有效。

## 2. 用户与场景（Who / When）

| ID | 场景 | 用户希望获得的结果 | 关联需求 |
|---|---|---|---|
| US-01 | 调整已确认的输入框样式和文案 | 直接完成与检查 | FR-01 |
| US-02 | 已明确数据、页面、行为与验收的 Demo | 直接生成简版技术方案并实现 | FR-02、FR-07、FR-09 |
| US-03 | Demo 只有大致目标，需梳理用户旅程与范围 | 先简版 PRD，再简版技术方案与实现 | FR-02、FR-09 |
| US-04 | 模拟订单问数链路，涉及多个模块 | 按可验证阶段完成，仍使用 simple 规格 | FR-05 |
| US-05 | 店铺隔离修复或接入生产订单数据 | 保留必要契约、评审与负向验证 | FR-03 |
| US-06 | 仅要求比较原型、写 PRD 或设计 | 完成请求的阶段，保持调用边界 | FR-04、FR-08 |
| US-07 | 已有 Feature 或定制模板的维护者 | 复用有效产物、批注和验收证据 | FR-06、FR-09 |

## 3. 总体业务流程

Prompt 读取任务、项目规则与已有规格 → 判断风险、复杂度和关键未知 → 选择需要的阶段与模板 → 向原子 Skill 交付明确上下文 → 依据阶段结果继续、补输入或调整组合 → 实现、评审与验收 → 按实际证据汇总交付。

单独调用 Skill 时，只完成所请求的能力并报告后续建议。连续推进由 Prompt 或已获连续任务授权的主 Agent 组织，不由阶段 Skill 固定启动后续流程。模型可以自主做常规阶段和模板选择；影响业务目标、权限语义或验收口径的未知交用户决定。

## 4. 功能需求（What）

| 编号 | 触发条件 / 当前问题 | 目标行为 | 可观察结果 |
|---|---|---|---|
| FR-01 | 明确、可逆、无业务契约变化的微小低风险修改 | 直接执行并做必要检查 | 未显式要求建包时不创建 Feature 或 ROADMAP 项 |
| FR-02 | simple 场景存在不同成熟度的需求输入 | 模型判断是否需要 PRD、技术方案及其他阶段，复用已有有效产物 | 需求充分可直接设计；需要梳理产品行为时先 PRD；记录选择理由与输入来源 |
| FR-03 | 权限、敏感数据、金额或不可逆数据变更带来高失败代价 | 补充相关契约、反例、实施前与实施后评审和必要验证 | 文档可精简，关键控制与验证保留 |
| FR-04 | 关键目标或技术可行性尚不明确 | 先执行有问题、方法和结束条件的澄清 / 探索 | 观察可复查，探索结果与业务功能验收分别报告 |
| FR-05 | 存在多个依赖模块或交付阶段 | 按可运行、可验证的阶段组织交付，模板档位单独选择 | 低风险复杂 Demo 仍可 simple；局部通过不代表全部完成 |
| FR-06 | 旧阶段入口固定要求前序文档，已有 Feature 需接续 | 动态接收有效 PRD、BRIEF、已归档需求、方案与证据，保留旧文档 | 缺少可选文档可接续；实质输入不足则报告缺口；不补空文件凑流程 |
| FR-07 | 用户希望使用轻量场景组合 | 新增 `my-simple-feature` Prompt，复用原子 Skill | 不新增同名源 Skill；安装器沿用现有 Prompt 入口机制 |
| FR-08 | 阶段能力与后续编排交叉 | Skill 只执行当前任务，Prompt 负责组合、重试、升级和收尾 | 单阶段调用无隐式跨阶段实现；技能回传产物、证据、阻塞与建议 |
| FR-09 | simple 与 standard 的文档深度不同 | 为 PRD 和技术方案提供独立 simple 模板，支持项目定制和增量更新 | 相同产物路径可以承载不同模板；生成 PRD / 设计不自动变成 standard |
| FR-10 | 多入口需要一致的规格档位名称与缺省行为 | 用唯一常量源定义 simple、standard、标签和默认值，脚本与模型共同读取 | 未知值明确报错；资源损坏不静默回退；风险与阶段安排不混入类型 |
| FR-11 | 用户需要在索引识别档位，档位又可能随需求变化 | BRIEF 保存 Feature 默认档位，ROADMAP 展示，目录继续使用 NNN-slug | 类型调整不改 ID / 路径；新五列索引与既有四列兼容，目标行展示同步且保留用户内容 |
| FR-12 | 开发者需要在方案评审时理解核心代码、掌控系统并判断质量 | 技术方案提供供评审的关键骨架与代表性代码，范围止于设计；两档位均按实际变更展开 | 少量代码内联，较多代码存为方案同目录的 Markdown 附录；核心决策可审，附录与正文一致，无完整实现 |

## 5. 使用交互

沿用自然语言输入，无新增 Web 页面或必填流程表单。`my-simple-feature` 是拟新增 Prompt，当前尚未实现。

示例选择说明：

- “本次 Demo 的页面、数据和验收已明确，使用 simple 技术方案，随后实现、代码评审与验收。”
- “先用简版 PRD 梳理演示范围与交互，再写简版技术方案，分阶段实现问数链路。”
- “发现生产数据与店铺权限边界，先补齐相关契约并评审，再继续受影响实现。”

`my-auto-feature` 保持完整需求交付的默认组合，`my-auto-design` 保持从明确需求 / 已有方案开始的默认组合；两者支持用户指定类型、已有产物接续和有依据的裁剪。simple 的默认组合集中在新 Prompt 中，具体职责见技术方案。

Feature 的规格档位在 BRIEF 明示。新 ROADMAP 增加“规格”列；已有四列索引保留结构，在本次新增或维护行的说明开头展示规格。目录和编号保持稳定，档位调整后原有链接继续可用。

## 6. 业务规则与约束（Rules）

| 编号 | 规则 | 关联需求 |
|---|---|---|
| BR-01 | 风险决定必要控制，复杂度决定拆分方式，不确定性决定澄清 / 探索；不以代码行数、耗时或文件数替代判断 | 全部 |
| BR-02 | 风险未知先核实；Demo 或 simple 标签不能证明风险低 | FR-01、03、04 |
| BR-03 | 阶段选择与模板档位分别判断。显式请求 PRD / 技术方案必须产出对应文件；明确请求完整流程则保留该组合 | FR-02、08、09 |
| BR-04 | 省略 PRD 需要已有充分需求输入：目标、范围、预期行为、验收与相关约束可追溯。设计不得据此编造业务决定 | FR-02、06 |
| BR-05 | simple 规格保留本次必需内容，模板删减不降低业务契约和质量要求。已有独立文档增量维护，BRIEF 保存简报与索引 | FR-03、06、09 |
| BR-06 | 升级保留 Feature ID、编号、人工批注与有效证据；契约变化影响的设计、用例和旧结果需同步或复验 | FR-05、06 |
| BR-07 | 项目已有评审、测试、审批要求为下限；连续开发授权不扩展为提交、发布或生产操作授权 | 全部 |
| BR-08 | 完成由所有本次承诺的当前证据决定；计划、文档、路径检查、探索成功或子任务启动不构成交付通过 | 全部 |
| BR-09 | Skill 的输入不足时报告缺口和可完成部分；是否补前序阶段由编排者决定。评审不得改写验收标准迎合实现 | FR-06、08 |
| BR-10 | 模板选择只影响组织形式和内容深度。既有项目模板、规则、有效产物及明确选择均需保留；缺必要能力时准确报缺口 | FR-06、09 |
| BR-11 | Profile 的合法值与默认值来自同一常量定义，持久化统一用规范标识；旧 Feature 缺字段才用默认值，未知值不视作缺省 | FR-10 |
| BR-12 | BRIEF 是 Feature 默认档位真源，ROADMAP 为展示；单产物模板覆盖不改变默认值。索引不同步时报告并在获授权维护中修正，不能反向覆盖真源 | FR-09～11 |
| BR-13 | 所有档位共用现有编号池和 NNN-slug 命名；档位变化不改 ID、目录和历史链接，旧四列索引不批量迁移或覆盖历史行 | FR-06、11 |

不新增工作流引擎、评分模型、远程审批系统或运行时依赖。

## 7. 范围与边界（Scope）

包含：七个 SDD Skill 的动态输入输出约定；Prompt 编排职责；新增 simple Prompt；simple PRD / 设计模板；Profile 常量与初始化记录；稳定目录、索引展示和四列 / 五列兼容；原有自动 Prompt 接续；风险、分段、升级、兼容及评测设计。

不包含：新增一组 simple 专属 Skill、自动发布、Web 流程编辑器、自动删除历史文档、替换用户定制或调整个人记忆存储机制。

本轮仅更新需求与设计，新增 Prompt、模板及源码任务保留待实施。

## 9. 验收标准（Acceptance Criteria）

沿用 AC-01～12 的标识并修订受影响预期，新增 AC-13～16；常量与索引补充增加 AC-17～20；2026-10-18 供评审代码设计增补 AC-21。原 AC 执行状态见[验收记录](../test/ACCEPTANCE.md)，AC-21 的新增宿主行为评测待执行，历史通过证据不覆盖本次增补。

| ID | Given / When | Then | 验证方式 |
|---|---|---|---|
| AC-01 | 已确认样式 / 文案、行为不变，通过 simple 入口请求修改 | 直接完成，无新增 Feature / ROADMAP 项；报告针对性检查 | 宿主调用轨迹与文件差异 |
| AC-02 | simple Demo 的目标、行为、数据和验收已明确，无既有方案 | 记录充分性依据，跳过 PRD，生成简版技术方案；按其实现、评审与验收 | 宿主完整交付，核对输入来源与产物 |
| AC-03 | 单点店铺隔离修复 | 明确身份来源、资源归属与拒绝策略，实施前评审、正反例验证、实施后评审 | 高风险行为评测 |
| AC-04 | 仅要求比较两种入口原型 | 记录问题、判定标准和观察，停在已授权探索范围；业务功能不标完成 | 宿主授权边界评测 |
| AC-05 | 百万行导出涉及容量与授权未知 | 先验证关键假设，按有退出条件的阶段推进；首段通过不标整个 Feature done | 分阶段行为评测 |
| AC-06 | simple 实施中发现生产数据或共享权限影响 | 暂停受影响实施，补相关规格和评审；保持 ID，受影响旧证据标待复验 | 风险变化评测 |
| AC-07 | 旧 Feature 无 profile，有 PRD、设计及人工批注 | 默认 standard 模板语义，沿原进度增量接续；旧初始化命令可用 | 兼容回归与宿主接续 |
| AC-08 | 部分安装、自定义 layout 或项目模板 | 精确处理实际依赖，遵守模板与路径优先级，缺能力不伪造调用，不覆盖定制 | 隔离装配与宿主评测 |
| AC-09 | 仅调用创建、PRD、设计或评审 Skill；另测完整 SDD 请求 | 单阶段只交付相应工作；完整请求由编排者继续完整组合 | 调用轨迹、产物和授权范围对照 |
| AC-10 | 测试失败、必要证据缺失或评审阻塞 | 报告未完成与缺口；不降低 AC 或将计划完成视为通过 | 失败及误报评测 |
| AC-11 | 低风险、多模块模拟问数 Demo | 允许 simple PRD / 设计，按可运行阶段交付并最终联调；不因复杂度单独强制 standard | 分阶段 simple 评测 |
| AC-12 | 分别在有 PRD / 无 PRD 的 simple Feature 中调用后续 Skill | 使用已登记有效输入，缺实质信息时报告；选中阶段按 layout 独立产出，不强求无关前序文件 | 逐阶段接续评测 |
| AC-13 | simple Demo 需要梳理用户旅程、范围与验收 | 先生成简版 PRD，再生成简版技术方案；保持 simple，不将内容全部挤入 BRIEF | 宿主完整交付与模板对照 |
| AC-14 | simple / standard 新产物、已有人工修改产物、自定义 simple 模板 | 按优先级使用正确模板；既有产物增量维护；相同 layout 路径不生成并行真源 | 模板/装配回归与宿主维护 |
| AC-15 | 某 Skill 返回前置输入不足或新增测试缺口 | Skill 返回明确缺口；Prompt 选择补输入、调用前序 / 测试能力或保留阻塞，再依据结果继续 | 原子能力与编排职责评测 |
| AC-16 | 无 PRD 路径形成方案后，又补充独立 PRD 或扩展规格 | 原路径增量维护，AC 编号和来源可追溯，唯一有效需求源明确，受影响结果复验 | 规格演进与中断接续评测 |
| AC-17 | 省略 / 显式设置 profile、输入未知值或常量资源缺失 / 损坏 | 脚本和模型使用同一合法值与默认值；非法值或资源错误在依赖写入前失败，旧 Feature 缺字段按默认接续 | 常量资源与初始化回归，宿主缺依赖评测 |
| AC-18 | 创建不同档位 Feature，之后调整默认档位或单产物模板 | 共用原编号池与 NNN-slug；调整不重命名、不断链接；单产物覆盖不改变 Feature 默认值及索引 | 初始化 / 路径回归与宿主维护评测 |

| AC-20 | Feature 档位调整中断，或 BRIEF 与 ROADMAP 已有差异 | 有效 BRIEF 为真源，准确报告待同步；授权维护仅修正目标行，不回滚外部编辑；两处复核一致后才报告成功 | 宿主修改、中断恢复及只读边界评测 |
| AC-21 | simple / standard 技术方案涉及核心架构、实体/类型、领域骨架、核心或高风险逻辑；另测无适用代码与自定义路径 | 提供可判断关键规则、边界和失败处理的最小骨架/代表性代码，标明位置、变更、审查问题与验证状态；少量内联，较多写方案同目录 Markdown 并双向链接，已有附录增量维护；无适用代码说明原因，不生成完整实现或写入生产源码 | small / large / 自定义路径 / 低风险 / 不充分与充分片段的六类宿主评测，见 test/prompt-evals.md |
