## 4. 发现

### W-01：无 PRD 接续需同步适配测试附属规范与沿用模板

- **严重性：Warning。是否阻塞：不阻塞进入实现。** 属于已明确架构下的配套范围缺口，修正不需要新业务决定或新增机制；应在 T-04 / T-08 中落实，交付前关闭。
- **事实：** [技术方案](../design/TECH_DESIGN.md)第 263～265、277、440 行要求测试继续沿用现有内容规范，允许以有效需求和 AC 接续，T-04 明列的测试附属文件仅为 `references/delegation.md`。实际 [测试 Skill](../../../assets/skills/my-create-test-plan/SKILL.md)第 49～51 行要求读取模板并遵循 `references/acceptance-cases.md`；该[附属规范](../../../assets/skills/my-create-test-plan/references/acceptance-cases.md)第 13、18 行仍将需求来源限定为 PRD，现有[测试模板](../../../templates/mai-specs/_templates/TEST_PLAN.tmpl.md)第 21 行也写为“PRD 验收 ID 或章节”。[标准技术方案模板](../../../templates/mai-specs/_templates/TECH_DESIGN.tmpl.md)第 3 行固定使用 PRD 来源字段，尚未给出无 PRD 的表达。
- **推断与触发：** 无 PRD 的 Feature 调用测试规划 / 验收，或以 standard 模板直接设计时，若只按任务清单修改主 Skill 而保留这些引用规范，模型会同时接收“可使用设计中的 AC”和“需求沿用 PRD”两种指令；可能多建 PRD、留下不存在的引用，或由不同模型自行选择解释。实际发生概率需要宿主评测，本轮未将其写成已复现故障。
- **影响：** 动态输入主契约仍可实施，但 AC-12 的接续一致性和 AC-14 的旧模板兼容缺少完整支撑。一般章节裁剪规则可以帮助模型判断，无法替代附属规范的明确来源约定。
- **最小修正：** 将 `references/acceptance-cases.md` 纳入 T-04，需求关联改为“已登记有效需求源的 AC / 章节”。同步调整分发的标准设计 / 测试模板提示；在 Skill 中明确保留旧项目模板时，按实际有效源填写原 PRD 来源位置，不因该字段产生 PRD 文件要求。沿用 preserve，不批量改写用户模板。
- **复查方式：** AC-12 / AC-14 增加一个组合场景：Feature 无 PRD，AC 位于技术方案，项目保留含 PRD 字段的旧测试模板；调用测试 Skill 后引用真实 AC，未新增 PRD，原项目模板及批注保持。再覆盖 standard 档位直接设计的来源记录；同时静态核对主 Skill 与必读附属文件一致。

未发现 Critical 项或其他影响实施可行性的缺口。
