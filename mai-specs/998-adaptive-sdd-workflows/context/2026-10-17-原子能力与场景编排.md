# 2026-10-17：原子 Skill 与场景 Prompt

来源：用户本轮对话及附图的文字整理。用于修订 Feature 998；本轮授权更新设计方案及相关规格，实现尚未开始。

## 用户明确的架构方向

- Skill 提供可独立调用、可复用的原子能力。
- Prompt 定义不同场景下的 Skill 组合模式。
- Skill 的输入与输出依据需求类型和当前上下文动态适配。
- simple / Demo 场景仍可以需要 PRD 和技术方案。模型根据实际需要判断直接进入技术方案，或先 PRD 再技术方案；阶段不设为一律必经。
- simple 需求可以使用专门的简版 PRD、技术方案模板，缩短内容与流程。
- `my-simple-feature` 是新增 Prompt，复用现有 Skill。
- 结合原有 998 设计更新方案。

## 对旧草案的修订依据

旧草案以 `lite` 将需求、设计和评审集中到 BRIEF，并将较复杂任务倾向 standard。本轮以原子能力、场景编排与差异化模板为主线：BRIEF 保存简报和流程索引；被选择的 PRD、设计阶段各自产出独立文档；低风险复杂 Demo 可以分阶段使用 simple 模板。

具体字段、模板路径、调用契约与评测规则由技术方案提出，仍待方案评审。用户明确的架构方向与技术细节的评审状态分别记录。

## 常量、目录与索引的补充决定

用户进一步询问是否统一类型常量，并在 Feature 目录规范和索引上体现。在讨论后明确同意按以下方向继续更新方案：

- Profile 首版定义 simple、standard，由一份常量源约束脚本与模型的值、标签和默认值。
- BRIEF 保存 Feature 默认档位，ROADMAP 显式展示；单产物模板可以另选并记录，不自动改变 Feature 默认值。
- 目录继续使用 `NNN-<slug>`，档位变化保持 ID、目录与已有链接。
- 新索引增加“规格”列，旧四列索引须兼容；初始化、模板和测试需同步设计。

具体采用“新索引五列、既有四列只在本次新增或更新行说明展示规格”的最小兼容方式，校验和中断恢复细节见技术方案，尚未实现。当前 998 的 BRIEF 与四列 ROADMAP 已手工登记 standard，用于本 Feature 的规格记录。
