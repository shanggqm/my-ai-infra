# 需求来源与流程裁剪示意

来源：2026-10-16 本次用户对话与附图。用途：为 SDD 流程裁剪需求、PRD 与技术方案提供输入。

## 用户明确要求

当前 create-feature、PRD、技术方案、review 与验收服务于完整 SDD。需要支持按需求复杂度和高风险区分流程；改文案、修小 bug 等微小改动无需 spec，直接完成；中小型需求需要更简化的 SDD。先创建需求，再完成技术方案设计。本次未请求实现。

## 附图可见内容转录

图片题为“流程裁剪”，以变更失败的风险和关键决策的不确定性为两条轴。主张先看做错的代价，再看还有什么没搞清楚。

- 低风险、低不确定：直接开发 / 轻量 SDD，示例为按钮“导出”改成“导出 CSV”。
- 高风险、低不确定：契约型 SDD，示例为订单查询补租户隔离，先明确权限契约并验证越权反例。
- 低风险、高不确定：探索优先，示例为比较工具栏按钮与更多菜单两种导出入口原型。
- 高风险、高不确定：分段承诺型 SDD，示例为百万行异步导出，先验证容量与授权下载，再分段实现和验收。

图中 my-simple-feature 作为轻量/探索示例入口，my-auto-feature 作为高风险例子入口；这些名字用于表达使用方式，实际可用性须以本仓库资产为准。图片说明：象限随任务条件变化，可重新判断。
