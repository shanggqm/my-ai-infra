## 范围与环境

覆盖原子 Skill、三种场景 Prompt、simple 模板、Profile 常量、初始化与新旧索引、实际行为及分发兼容。无需数据库或生产服务。本次不发布包、不修改真实宿主配置，不把路径/关键词检查当作模型行为验收。

自动化使用 Node.js 22+、项目 node:test 和隔离临时项目/个人库；测试副本可以注入文件系统失败、旧模板、CRLF 和并发修改。宿主评测使用安装当前资产的隔离项目，记录宿主及模型、输入、资产基线、实际调用、diff、文件与执行结果；每个案例从干净 fixture 开始。可复用的执行记录保存在本 Feature 的测试目录，原始大日志放忽略的 dist/ 下并记录摘要。缺凭据或宿主能力时标记待验证及具体阻断，承诺仍留在范围内。

## W-01 专项复查

- **W-01a（simple）**：建立无 PRD 的 Feature，设计内 AC-01/02 为真源；保留旧项目 TEST_PLAN 模板中的“PRD AC”表头及人工批注。调用测试 Skill 规划与执行可用检查。要求引用设计实际 AC、说明旧表头的语义、不创建 PRD、不改模板原文/批注；记录输入源、模板哈希及实际产物。
- **W-01b（standard）**：充分 BRIEF/材料直接生成 standard 技术方案，旧项目设计模板含固定 PRD 字段；填写实际需求来源并记录 AC，不生成虚构 PRD 链接；后续审查/测试采用同源。
- **W-01c（资源审计）**：核对测试 acceptance-cases、delegation、各 Skill 元信息以及分发 standard 设计/测试模板，确保没有隐藏的必备 PRD 前提。新分发模板改为“有效需求来源 / AC”；已安装项目模板由 preserve 保留。

## 自动化、分发与命令

在仓库根执行，以下为计划使用的命令；本轮实际执行及结果见验收记录：

1. `node --test test/feature-init.test.mjs test/feature-layout.test.mjs test/prompts.test.mjs test/single-source.test.mjs test/release-quality.test.mjs`：按实现新增行为断言；保留锁、回滚、字面占位符、素材、软链接和越界测试。
2. `npm run verify`：资源、语法、引用与完整 node:test。
3. `npm run release:check`：打包后隔离安装/移动/更新/冲突/选择安装；核对 Profile 注册表、共享契约、simple 模板、新 Prompt 唯一正文及四工具原生入口。
4. Feature 默认布局校验及本目录相对链接核对；路径通过不等于阶段/验收通过。

没有 Web 行为变更时按方案不额外触发浏览器回归；若实施改变 Web 行为则执行 `npm run test:web`。正式发布另行授权。

## 宿主矩阵和完成条件

至少一个受支持宿主执行 H-01～20 全组（A 用例同时有自动化证据）；其他 Codex / Claude Code / Cursor / Copilot 宿主核对实际入口发现和“直接设计”“PRD + 设计”“高风险”三种代表路径。装配文件存在与模型实际执行分别记录。无法运行项列出宿主、原因、复验步骤，保留未通过状态。

任务分为计划、已实现、已执行通过、失败、待验证，证据必须关联当前变更基线。全部承诺有有效证据、评审问题关闭后方可结项；W-01 的资源修正与实际行为复查分别判定。实现自检不替代代码审查与交付验收。
