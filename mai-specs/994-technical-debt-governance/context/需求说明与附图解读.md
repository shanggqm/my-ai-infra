# 技术债治理需求与附图解读

来源：用户本轮对话、附件 pasted-text.txt 和两张可见图片；2026-10-18 归档。图片内容根据会话可见内容整理，未保存图片二进制。

## 用户要求

技术债治理需在 my-ai-infra 各环节体现，新增 Skill 使用用户明确名称 my-analyze-debt，明确典型债务、分析流程、输出模板。创建新 Feature，使用 my-auto-design 完成方案；开发前停止，等待用户阅读方案。

## 附图约束

- 事前：my-init-repo-memory 按当前架构与已确认约束维护 AGENTS.md；my-create-design 设计后由 my-review-design 对边界、复用、契约与复杂度再次检查。
- 事中：my-review-code 从本次 Diff 沿调用链审新增或放大债务，区分历史存量，说明后续修改成本、最小修复与复验。
- 事后：独立分析模块或系统存量债务，跨模块核对证据及持续修改成本，按收益排序，给出范围有限且可验证的偿债任务。
- 治理结果回到当前架构约束、契约与回归测试，支持下一轮迭代；优先关注业务核心、频繁修改、多人共同依赖的交汇点。
- 附图的 my-analysis-debt 是尚未实现时的示意名称，本需求以 my-analyze-debt 为唯一正式名称，不据此增加历史兼容别名。

## 材料使用边界

用户提供的12类债务作为分类与案例输入；原文研究数据、引用和长期影响排序保留出处，未经本轮外部核验，不将其推广为普遍发生率或自动优先级。认知与责任情况需要团队证据，不能从代码外观或提交者身份推断。

## 本轮范围

只创建需求包、设计与方案评审记录。新 Skill、已有 Skill/Prompt/模板修改及自动化测试全部列为开发任务，不写入分发源。此前讨论的模板目录归属迁移作为相关背景，不并入本 Feature；新 Skill 的模板直接设计在自身 assets/templates/ 下。
