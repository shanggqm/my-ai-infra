# PRD：存量 OpenSpec 项目迁移

> 状态：待评审 · Feature 991 · Profile：standard · [项目 PRD 模板](../../_templates/PRD.tmpl.md)

[返回需求简报](../BRIEF.md) · [需求依据](../context/_INDEX.md)

本文是 Feature 991 的需求与验收标准维护源。已确认目标是让存量项目能从 OpenSpec 迁移到 my-ai-infra。下列模式、首版边界及文案为评审草案，参考当前项目规则、已安装的接续契约和 OpenSpec 官方资料。

## 1. 背景与目标

OpenSpec 项目通常已有现行规格、进行中的变更及归档记录。维护者希望采用 MAI 工作流，同时保留这些资产的含义和开发进度。当前 MAI 支持在已有项目中初始化规格工作区，也提供 Feature 编号、布局与阶段约定；当前仓库源码尚无 OpenSpec 导入或归档入口。

迁移后，团队能回答三个问题：当前规格在哪里维护、正在做的变更下一步是什么、已交付的行为从哪次变更演进而来。已有材料够用时，团队可以直接接续，无需重写 PRD、设计或任务。

## 2. 用户与场景

|---|---|---|---|

## 3. 总体流程

1. **预览**：选择项目和迁移模式。CLI 盘点源文件、目标路径、预计创建或复用的 Feature、有效规格归属、缺件、冲突和 revision。可取消，退出后项目保持原样。
2. **执行**：维护者按预览明确提交。成功时列出实际 Feature 与索引；源文件或目标状态有变化时重新预览。遇到冲突或异常时保留现场，并报告阻塞路径与恢复动作。
3. **接续**：通过 BRIEF 查阅 PRD、设计和任务。单个或批量导入后，现行规格和归档仍由 OpenSpec 维护。整仓切换后，在途 change 保持 draft；已归档 change 的 Phase 为 done，列在 ROADMAP 已完成。`history/` 只保留归档原文供阅读。

## 4. 功能需求

| 编号 | 触发与输入 | 预期行为与可观察结果 |
|---|---|---|
| FR-01 | 指定项目，选择单个、多个在途变更或整仓切换 | 输出只读预览：源与目标、计划动作、跳过或阻塞项、归档归属、revision。找不到源或选中项时，指出路径或变更 ID。仅匹配当前预览的显式提交可写入。 |
| FR-02 | 导入一个 `openspec/changes/<id>/` 在途变更 | 建立或复用对应 Feature；保留提案、差量、设计、任务、已有 PRD 及可识别关联资料，登记原路径与目标位置。其他变更、现行规格和历史仍由 OpenSpec 管理。 |
| FR-06 | 选择多个指定的在途 change 或全部在途 change | 一次预览和提交，为每个 change 建立或复用独立 Feature，保留各自材料、任务与映射；不涉及的 change 保持原样。OpenSpec 继续管理现行规格及各 change 归档。 |
| FR-03 | 整仓切换 | 将 `openspec/specs/` 的现行规格带入 MAI 并保留能力路径；在途变更对齐为 draft Feature，登记到 ROADMAP 规划中；已归档 change 按同一布局对齐，Phase 为 done，登记到 ROADMAP 已完成。`mai-specs/history/` 保留归档原文供阅读。提交成功后记录 MAI 已接管的范围；原 `openspec/` 保留为切换时的快照，已有 OpenSpec 工具配置由维护者处置。 |
| FR-04 | 打开迁入 Feature | BRIEF 登记有效需求源、设计、唯一的当前任务清单、决策和证据；缺失项标明。保留任务编号、顺序和勾选状态；对照代码和已有批准，从首项前置条件满足的未完成任务继续。提案和差量要求对齐为 `spec/PRD.md`，设计和任务对齐为 `design/TECH_DESIGN.md`。对齐结果是有效需求来源。不把 OpenSpec 目录或差量原文另存进 Feature，也不另建空占位文档。缺少关键依据时明确补充或复核项。 |
| FR-05 | 整仓切换 | 复制现行规格和 OpenSpec 历史原文。已归档 change 对齐为 Feature，并用 MAI 既有完成状态记录：Phase 为 done，ROADMAP 位于已完成。差量要求只进入对应 Feature 的 PRD，不改写已复制的现行规格。本次不新增 Feature 归档命令，也不改 Skill。 |

## 5. 业务规则与约束

| 编号 | 规则 | 关联 |
|---|---|---|
| BR-01 | 区分现行规格、待生效差量和历史。导入在途变更时，差量要求写入 Feature PRD，不改写现行规格；整仓切换不重放历史差量。单变更导入时，OpenSpec 继续维护现行规格和归档。整仓切换成功后，已复制的现行规格和历史保存在 MAI 工作区。 | FR-02、FR-03、FR-05 |
| BR-02 | 记录来源项目内的变更路径与目标 Feature 的稳定映射。相同输入重复执行时复用编号且不重复登记；发现源或目标有修改时，预览差异，禁止静默覆盖。先单导入再整仓切换时，复用已有 Feature；两边独立修改、同名但来源不同或归属不明时，维护者解决冲突后再预览。 | FR-01、FR-02、FR-03 |
| BR-03 | 遵循项目的 Feature 编号、Profile、布局及 ROADMAP 约定。已勾选的任务和旧评审、旧测试结果按原样保留，须核对当前代码和适用性。迁移不把仍在活动目录的 change 标为完成。已归档 change 沿用 MAI 的完成状态：BRIEF Phase 为 done，ROADMAP 行在已完成。这记录来源状态，不表示迁移重新做了评审。 | FR-02、FR-03、FR-04、FR-05 |
| BR-04 | 迁移识别标准 ADDED、MODIFIED、REMOVED、RENAMED，并把可识别内容写入 Feature PRD。未支持的差量标题记入待确认。迁移不把这些操作应用到 `mai-specs/specs/`。 | FR-05 |
| BR-05 | 对所选迁移范围逐项区分未提供、空、不可读和不支持的内容。缺少可选材料时可保真导入并标缺口；无法识别、读取或保全关键资料时阻塞相关提交。整仓切换须覆盖预览列出的所有关键输入，任何阻塞项都使整次切换保持未完成。 | FR-01、FR-02、FR-03 |
| BR-07 | 批量导入是一个整体：任一选中项缺失、冲突或无法保全时整批阻塞；执行中断按整体恢复，不报告部分完成。每个已导入项按既有映射复用；不自动识别或包含依赖变更；保留原始资料，预览提示维护者人工核对 change 之间的依赖及顺序。 | FR-06 |
| BR-06 | 迁移保留任务勾选。仍在活动目录的 change 不标为完成，也不根据勾选推断验收通过。已归档 change 只按来源已完成写入 MAI 的 done 状态。后续完成度沿用 MAI 既有阶段。 | FR-04、FR-05 |
| NFR-01 | 所有写入限制在指定项目内；不沿不安全的软链接读写，保留原 OpenSpec 文件和既有 MAI 用户资料。预览全程只读，提交加锁并复核源与目标；预览列出受影响文件，维护者在迁移、归档或恢复执行期间暂停编辑这些文件。遵守该约定时保留已有用户资料；对不参与锁的外部编辑器，最终写前复核与替换之间的并发窗口首版不保证检测。执行失败时回滚可确认属于本次操作的写入，异常无法自动恢复时保留现场并指出恢复材料和下一步。 | FR-01、FR-02、FR-03、FR-05 |
| NFR-02 | 迁移在本地运行，常规迁移无需安装 OpenSpec CLI、联网或调用模型。保留原文及可追溯的来源映射；内部相对引用应可访问或明确列为待修复。 | FR-01、FR-02、FR-03、FR-04 |

## 6. 范围与边界

- **首版入口**：CLI 及配套使用说明；迁移由维护者显式触发。已有项目可使用 `mai init` 装配工作流；迁移动作和资产安装分别确认。
- **首版输入**：项目根目录下的标准 OpenSpec Markdown 工作区，包括按能力分组的现行规格、在途变更、变更差量和归档历史。保留未识别附件或在预览中报告无法保全的项目。自定义工作流、非标准规格根目录及需特殊语义的配置需识别并说明支持边界。
- **本期排除**：Web 入口、后台双向同步、自动卸载 OpenSpec 或清理宿主配置、自动运行任务、自动判断历史评审或验收通过。长期规格的目标路径和命令参数由技术设计确定。

## 7. CLI 交互与文案

沿用 `mai` 的本地 CLI 操作方式。以 `mai migrate openspec` 明确迁移来源，先用 `--dry-run` 查看迁移模式、范围、规格维护源和提交方式；核对后用本次预览的 `--revision HASH` 显式提交。交互与非交互调用均遵循此流程。错误包含路径或变更 ID 及可执行的恢复动作。以下文案供评审，尖括号内为运行时值。

| ID | 位置或状态 | 文案 |
|---|---|---|
| COPY-01 | 可提交的迁移预览 | 已预览迁移：<模式>。将新增 <数量> 个 Feature，复用 <数量> 个 Feature。核对清单后，使用本次 revision 提交。 |
| COPY-09 | 批量迁移预览 | 请人工核对所选变更与其他 change 之间的依赖关系及开发顺序。 |
| COPY-08 | 迁移、归档或恢复的可提交预览 | 执行期间请暂停编辑预览列出的受影响文件，完成后即可继续编辑。 |
| COPY-02 | 源或目标变化 | 项目内容自预览后已变化，未执行迁移。请重新预览。 |
| COPY-03 | 数据冲突或不支持 | 无法继续迁移：<路径>（<原因>）。请<处理建议>后重新预览。 |
| COPY-04 | 单变更迁移完成 | 已将 <变更 ID> 导入 Feature <编号>。OpenSpec 继续维护现行规格和归档。 |
| COPY-07 | 批量导入完成 | 已导入 <数量> 个 OpenSpec 变更。OpenSpec 继续维护现行规格和归档。 |
| COPY-05 | 整仓切换完成 | 已切换到 my-ai-infra。现行规格在 mai-specs/specs。已归档 change 已对齐为 Feature，Phase 为 done，列在 ROADMAP 已完成。原文在 mai-specs/history，供阅读。原 OpenSpec 文件已保留。 |

数量使用非负整数（可为 0）；模式为“单变更导入”、“批量变更导入”或“整仓切换”；路径与变更 ID 按实际值展示。空工作区应显示无可迁移项，不输出成功文案；预览失败时不提供可执行的提交指令。

## 8. 验收标准

| ID | Given / When / Then | 关联 |
|---|---|---|
| AC-01 | 给定含现行规格、两个在途变更及归档记录的项目，分别预览两种模式；应列出各自范围、维护源、目标与 revision，预览前后的项目文件和目录保持一致。无源、空目录或选择归档 ID 时，明确原因且不写入。 | FR-01、BR-05、NFR-01 |
| AC-02 | 给定变更 A 含提案、设计、差量、附件、部分勾选的任务，变更 B 独立在途；提交单变更导入 A 后，索引可追溯，任务编号及勾选状态一致，差量未应用，B、OpenSpec 的现行规格与历史文件内容不变，结果给出 OpenSpec 归档交接提示。 | FR-02、BR-01、NFR-02 |
| AC-03 | 给定含多层能力目录、多个在途变更、历史归档和自定义 MAI 布局的项目；提交整仓切换后，能通过索引找到等价的现行规格、全部在途 Feature，以及已归档 change 对齐出的 Feature。在途 Feature 为 draft，已归档 Feature 的 Phase 为 done 且位于 ROADMAP 已完成。现行规格与切换时源现行规格等价并保留已同步结果；迁移不应用尚未生效的在途差量，历史差量未重放，OpenSpec 源文件与用户资料保留，维护源指向 MAI。 | FR-03、BR-01、BR-03、BR-05、NFR-02 |
| AC-04 | 给定已单导入 A；以同样输入重新迁移或随后整仓切换，沿用 A 的编号且 ROADMAP 只有一条记录。若两侧都有独立修改或目标有其他来源的同名内容，预览显示冲突，执行不覆盖内容。 | FR-02、FR-03、BR-02 |
| AC-05 | 给定 A 有部分任务完成、有效设计及旧测试记录，B 缺设计或差量；打开对应 BRIEF 并接续时，能定位唯一的当前任务、`spec/PRD.md` 中的需求来源与下一项可执行任务。旧证据注明适用性待核对；缺失材料可见，OpenSpec 目录不进入 `context/`，变更不标为完成。 | FR-04、BR-03、BR-05 |
| AC-06 | 给定已切换的项目，在途 change 与已归档 change 的差量要求都出现在对应 Feature 的 PRD 中。在途 Feature 为 draft；已归档 Feature 的 Phase 为 done。`mai-specs/specs/` 与切换时的源现行规格字节一致，归档原文可从 `mai-specs/history/INDEX.md` 阅读。重复执行 `--all` 不改写这些规格。 | FR-05、BR-04、NFR-01 |
| AC-07 | 给定差量标题无法识别、源和目标都有独立修改，或任务材料缺失；预览把无法识别的差量记入 PRD 待确认，冲突和缺失按迁移规则阻塞或标明。现行规格和未提交的目标保持原状。 | FR-04、FR-05、BR-04、BR-06 |
| AC-09 | 给定 A、B、C 三个活动 change；预览选中 A、B 时按项展示目标、任务、人工核对依赖的提示和一个 revision，项目无写入；提交后两项各有唯一 Feature 与映射，保留任务与差量，C、现行规格及历史不变，归档仍由 OpenSpec 管理。重复执行或随后整仓切换复用已有编号。 | FR-06、BR-01、BR-02、BR-07 |
| AC-10 | 给定多个活动 change，选择全部在途变更时仅导入当前活动项，保留 OpenSpec 维护源；空列表有明确提示。指定项重复、缺失、已归档、无效，或任一项冲突时整批拒绝。预览后新增活动项或修改选中项/目标索引，再提交旧 revision，均拒绝且不丢失修改。执行中途失败按整体回滚；无法安全自动恢复时保留恢复材料并阻塞后续写入。 | FR-06、BR-07、NFR-01 |
| AC-08 | 预览后修改源资料、目标索引或现行规格，再提交旧 revision；应拒绝且保留修改。另验证参与工作区锁的写入互斥、写前复核发现外部变化时保留修改、不安全软链接、不可读关键资料和提交中断；项目外路径和原 OpenSpec 保持原样，失败不得留下有效切换或归档状态，必要时可按报告恢复。 | FR-01、FR-03、FR-05、BR-05、NFR-01 |

验收建议使用隔离项目进行 CLI 集成验证，包含单导入后整仓切换、整仓归档、并发与失败恢复。另使用一组实际项目脱敏样本验证链接、任务接续和有效来源；勾选状态、文件落盘或静态检查均不能代替实际接续和归档验证。
