# 993：复用项目既有格式化规范的 Hook

需求来源：2026-10-25 用户要求定义 Hook 资产，在 init 检测项目根目录已有格式化配置，存在时尝试调用格式化脚本，缺脚本直接结束，不默认添加格式化配置。

## 行为与验收

- AC-01：无根目录格式化配置时不安装或注册本 Hook，不生成格式化配置。子目录、父目录配置及外部链接不作为根目录配置。
- AC-02：已有配置时按所选 Coding 工具装配资产和原生注册。覆盖 Codex / Claude Code / Cursor / Copilot 的主任务轮次结束事件。
- AC-03：执行时再次检测，只复用项目已有 package script、约定文件或 Make / Just 目标；没有入口或运行工具时正常退出。
- AC-04：保持仓库既有格式化脚本的参数、范围与根目录 cwd。初始化和只读检查不执行脚本，不下载工具，不改写格式化配置。
- AC-05：注册合并保留其他宿主设置和 Hook，重复同步幂等。移除格式化配置后同步撤回本注册；取消工具沿用现有清理契约。
- AC-06：预览包含检测依据和命令来源，配置或脚本变化使 revision 失效。共享配置损坏、结构未知、链接或受管 Hook 定制时保留现场并报告未完成。
- AC-07：脚本失败、超时、并发和重复续跑有确定的结束/跳过行为。实际执行结果与宿主发现验证分别报告。

首版入口策略按用户“找不到脚本就结束”采用只复用已有脚本。整个仓库脚本可能修改已有脏文件，文档明确这一范围。可选询问未获得回答时不扩大到直接执行各语言格式化器。

不包含：个人记忆 Hook、全局常驻服务、Git 提交 Hook、自动配置格式化工具、递归探测 monorepo、宿主信任自动批准。
